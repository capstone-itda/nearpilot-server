# 실제 기기의 관측과 명령을 확인하는 로컬 시험

- 담당: 작업 지시자 (서버 시험, 최소 펌웨어)
- 요구사항: FR-04, FR-05, FR-06, FR-07, FR-13, FR-16, FR-18, FR-22, NFR-03, NFR-07, NFR-08, NFR-12
- 근거: `docs/product.md`, `docs/requirements.md`, `docs/architecture.md`, `specs/firmware-contracts/spec.md`

## 1. 왜

실제 기기의 RSSI가 추정기에 도착하는지 확인할 도구가 없다.
앱 없이 명령과 결과를 연결해서 확인할 절차가 없다.
현재 담당자는 ESP32를 가지고 있지 않다.

## 2. 무엇

- 입력: 별도 시험 설정, 기기의 MQTT 보고, 로컬 콘솔 명령이다.
- 출력: RSSI, 사후확률, 기기 상태, 판정, 명령 결과의 화면 출력과 JSONL이다.
- 바뀌는 상태: 별도 시험 DB와 기기의 명령 기록이다.
- 약속: 실제 CORE 허가 경로로 명령을 보낸다. 앱과 외부 API를 쓰지 않는다.
- 약속: 기기가 없어도 기존 시뮬레이터로 같은 경로를 확인한다.
- 약속: 최소 펌웨어는 ESP32의 BLE 수신과 MQTT 보고, 명령 도착을 시리얼 로그로 확인한다.
- 약속: 모든 시험 기기에 같은 펌웨어를 쓴다. 기기 ID, MQTT 계정, Wi-Fi, 서버·시각원 주소, 시각 신뢰 값은 USB로 한 번 주입하고 NVS에 보존한다.
- 약속: 설정을 마친 기기는 전원을 켜거나 EN을 누르면 사람의 조작 없이 연결한다. 기기와 서버 로그에서 준비 단계와 차단 이유를 확인한다.

### 자동 연결 순서

| 단계 | 기기 | 다음 단계로 가는 조건 |
|---|---|---|
| 1 설정 | NVS 설정을 읽는다. 없거나 손상되면 `CONFIG_MISSING`이고 네트워크를 시작하지 않는다 | 설정 확인 |
| 2 Wi-Fi | 접속하고 끊기면 재시도한다 | IP 획득 |
| 3 시각 | 설정한 시각원으로 동기화한다. 동기화, 검증된 오차 한도, 신뢰 기간을 모두 확인한다 | 시각 신뢰 |
| 4 MQTT | 기기 계정으로 접속하고 새 `session_id`로 `cmd`·`safety_check`를 구독한다. 시각 신뢰와 별개로 진행한다 | 구독 성공 |
| 5 발표 | 연결마다 시각을 신뢰한 뒤 retained `announce`를 한 번 보낸다. 그다음 `status`와 명령 기록을 보고한다 | 발표 발행 |
| 6 기기 준비 | `NODE_READY`를 한 번 기록한다. 조건이 깨지면 `NODE_NOT_READY`와 이유를 기록한다 | — |
| 7 서버 준비 | 시험 도구가 연결 확인, 신뢰, 장소, `FAULT`, 실행 가능 여부의 변화를 `node_readiness`로 기록한다 | `ready=true` |

- 기기 준비는 기기 쪽 연결 조건이다. 실행 허가가 아니다. 실행 가능 여부는 서버만 판단한다 (NFR-07).

## 3. 제약

- MQTT v1의 필드와 전달 설정을 유지한다 (FR-04, FR-05, FR-07).
- 시험 명령도 기존 판정과 실행 직전 재검사를 거친다 (FR-06, FR-18).
- 근접 확률을 고정하지 않는다. 실제 추정기를 호출한다 (FR-16).
- 합성 모델을 실측 모델로 표시하지 않는다 (FR-16, FR-22).
- 실제 기기의 시각 오차는 측정 전까지 미설정이다 (NFR-08, NFR-12).
- 시리얼 출력과 GPIO 제어 신호만으로 물리 성공을 확정하지 않는다 (FR-07).
- 펌웨어는 구동 전에 명령을 NVS에 기록한다. 기록을 자동 삭제하지 않는다 (FR-06, FR-22).
- 자격정보와 MQTT 본문 전체를 확인 로그에 쓰지 않는다 (NFR-08).
- 기기 인증은 기기별 MQTT 사용자명·비밀번호와 브로커 ACL이다. 앱·호스트 토큰과 섞지 않고 새 토큰 체계를 만들지 않는다 (NFR-08).
- 미검증·만료된 시각에서는 status·RSSI 보고와 새 출력을 차단한다. 재시도와 재부팅으로 이 차단을 우회하지 않는다 (FR-07, NFR-12).
- 설정 주입은 명령 기록 NVS 영역을 지우거나 바꾸지 않는다. 재부팅이나 재주입으로 서버의 `FAULT`를 해제하지 않는다 (FR-06, FR-22).

## 4. 경계

### 고치는 곳

- `server/tools/node_lab/`, `server/tests/tools/`, `server/tests/integration/`
- `firmware/node_lab/`
- `.gitignore`의 시험 생성물 규칙
- 이 spec과 `specs/firmware-contracts/spec.md`의 시험 환경 결정

### 고치지 않는 곳

- `docs/`, 기존 `server/src/`, `shared`, DB 스키마, MQTT 계약, `.github/`

### 다른 영역과 닿는 곳

| 계약 | 사용 또는 제공 | 상대 영역 |
|---|---|---|
| Runtime, CORE, 근접 추정기 | 기존 구현 사용 | CORE |
| AdminService, AdminRepository | 시험 계정과 등록한 시험 기기 설정 | CORE, DB |
| MQTT v1 | 펌웨어와 기존 IOT 사이 보고·명령 | IOT |
| SimNode, SimDevice | 보드 없는 연결 검사 | 기기 시뮬레이터 |

### 만들지 않는 것

- 앱 인증, REST, WebSocket과 운영 UI다.
- 실제 사물함, 스피커, 반납 센서와 운영용 펌웨어다.
- 측정하지 않은 시각 오차, 근접 품질과 물리 완료의 보증이다.

## 5. 예외 상황

| 상황 | 기대 동작 | 테스트 |
|---|---|---|
| 생성할 폴더가 이미 있다 | 기존 설정과 기록을 덮어쓰지 않는다 | `test_FR22_init_refuses_existing_directory` |
| 다른 기기가 발표한다 | 등록한 시험 기기만 설정한다 | `test_FR13_lab_only_configures_listed_nodes` |
| 비콘이 없다 | 관측 없음으로 표시하고 실행을 차단한다 | `test_FR06_lab_missing_beacon_blocks_command` |
| 실제 기기의 시각 오차가 없다 | 기존 IOT 차단과 진단 로그를 유지한다 | `test_FR07_hardware_has_no_default_clock_skew` |
| 명령을 보냈다 | 요청 ID, 명령 ID, 결과를 연결해서 기록한다 | `test_FR06_lab_real_broker_command` |
| GPIO나 완료 센서가 없다 | 시리얼로 수신을 확인하고 결과는 unknown이다 | 펌웨어 검토와 실제 보드 후속 확인 |
| 같은 명령이 다시 온다 | 기존 결과를 반환하고 다시 처리하지 않는다 | 펌웨어 명령 기록 검증 |
| 수신과 종료가 겹친다 | 실행 결과를 임의로 성공 처리하지 않는다 | 기존 runtime 회귀 검사 |
| 설정이 없다 | `CONFIG_MISSING`이고 Wi-Fi·MQTT를 시작하지 않는다 | 실제 보드 확인 |
| 주입할 기기가 시험 목록에 없다 | 주입하지 않는다 | `test_FR13_provision_rejects_unlisted_node` |
| 기기 비밀번호 파일이 없다 | 주입하지 않는다 | `test_NFR08_provision_requires_password_files` |
| 주입 기록을 남긴다 | 비밀번호와 Wi-Fi 비밀번호를 쓰지 않는다 | `test_NFR08_provision_log_has_no_secrets` |
| 서버에 측정 오차가 없다 | 기기에 미검증 값 `-1`을 주입한다. 기기는 시각을 신뢰하지 않는다 | `test_NFR12_provision_uses_server_clock_bound` |
| 기기가 주입을 거부하거나 다시 읽은 값이 다르다 | 실패로 끝낸다 | `test_FR22_provision_fails_on_reject_or_mismatch` |
| 명령 기록이 있는 기기의 ID를 바꾼다 | 기기가 거부한다. 기록을 지우지 않는다 | 펌웨어 검토와 실제 보드 확인 |
| Wi-Fi·브로커·시각원에 닿지 않는다 | 실패 코드와 다음 시도 간격을 기록하고 상한까지 늘려 재시도한다 | 실제 보드 확인 |
| 시각 신뢰가 만료된다 | `CLOCK_TRUST_EXPIRED`와 `NODE_NOT_READY`를 기록하고 보고·출력을 차단한다 | 실제 보드 확인 |
| 서버·시각원 주소가 바뀐다 | USB로 다시 주입하고 재시작한다. 새 시각원은 다시 동기화한 뒤 신뢰한다 | 실제 보드 확인 |
| 준비 상태가 바뀐다 | 바뀐 때만 `node_readiness`를 기록한다 | `test_FR13_lab_logs_readiness_changes_only` |
| 부팅 로그 순서가 계약과 다르다 | 부팅 검사를 실패로 본다 | `test_FR04_boot_check_requires_contract_order` |

## 6. 결정

- 기존 Runtime을 직접 호출하는 로컬 콘솔을 쓴다 — 담당자가 2026-10-22에 선택했다.
- 별도 시험 폴더와 JSONL 확인 로그를 쓴다 — 담당자가 같은 제안을 승인했다.
- PlatformIO, Arduino-ESP32, NimBLE와 NVS로 최소 시험 펌웨어를 준비한다 — 담당자는 ESP32만 쓰고 추가 보드가 필요 없으면 넣지 말라고 지시했다.
- 기본 출력은 시리얼이다. 내장 LED 핀은 선택 설정이다 — ESP32의 실제 모델과 내장 LED 유무를 아직 모른다.
- 클라이언트 앱이 없으면 보유 ESP32 한 대를 선택 iBeacon 송신기로 쓴다 — 기존 비콘 입력을 재현하며 추가 보드 구매를 요구하지 않는다.
- 시리얼·GPIO 시험 결과는 unknown으로 보고한다 — 완료 관측 계약을 새로 정하지 않는다.
- 시험 모델은 좌표 기반 합성 초기값이다. 모델 JSON을 실측 파일로 교체할 수 있게 한다 — 기능 연결과 품질 검증을 구분한다.
- 명령 기록의 한도를 만나면 새 명령을 실행하지 않는다 — 기록을 자동 삭제하지 않는 계약을 유지한다.
- 서버 시작 뒤 새 기기가 발표하면 시험 도구가 Runtime을 정상 종료하고 다시 시작한다 — 기존 복원 서비스는 최초 목록만 읽는다. 실행 가능 검사를 우회하지 않는다.
- 최초 설정은 USB 시리얼 주입이다 — 담당자가 2026-10-23에 Wi-Fi 설정 페이지, NVS 이미지, 기기별 빌드 대신 선택했다.
- 주입 설정은 명령 기록과 다른 NVS 이름공간에 JSON 하나로 저장한다 — 키 하나의 쓰기라 부분 갱신이 남지 않는다. 명령 기록을 건드리지 않는다.
- 주입 값은 시험 폴더에서 읽는다. MQTT 주소와 기기 시각 오차는 `server.toml`에서, 비밀번호는 `.env.*` 파일에서 읽는다 — 서버와 기기가 같은 오차 값을 쓴다. 비밀번호를 명령행 인자로 받지 않는다.
- 저장한 뒤 기기는 재시작해서 새 설정을 적용한다 — 시각원 변경 뒤의 신뢰를 처음부터 다시 확인한다.
- MQTT는 시각 신뢰 전에도 접속·구독한다. 발표는 그 연결에서 시각을 신뢰한 뒤 보낸다 — 담당자가 2026-10-23에 선택했다. 미검증 시각의 `sent_at`이 retained로 남지 않는다.
- Wi-Fi와 MQTT 재시도 간격은 설정한 최소값에서 두 배씩 늘려 설정한 상한에서 멈춘다. 성공하면 최소값으로 돌아간다.
- 기기 준비 로그는 상태가 바뀔 때와 상한 간격마다 남긴다 — 매 반복마다 남기지 않는다.

## 7. 가정

- USB 시리얼의 진단 요청과 응답으로 기기 시각을 실측한다. 요청 직전과 응답 직후의 서버 시각으로 오차 구간을 계산한다.
- 진단 요청은 시각만 읽는다. 동기화 여부, 동기화 후 경과 시간과 요청 식별자를 응답한다. 명령 실행을 허가하지 않는다.
- 측정 도구는 동기화 전 표본, 시각 점프와 응답 지연 초과를 거부한다. 측정 기간, 표본 수와 오차 구간을 JSONL에 보존한다.
- 짧은 실측은 같은 환경의 연결 시험에만 쓴다. 장시간 동작과 시각원 단절을 포함한 운영용 최대 오차 검증을 대신하지 않는다.
- 시험 허용 오차는 실측 구간의 최대 절댓값에 명시한 여유를 더한다. 서버와 펌웨어에 같은 값을 적용한다.

- 실제 보드 모델과 핀을 확인하기 전에는 esp32dev의 컴파일만 검사한다.
- 실제 시각 오차는 보드를 받은 뒤 측정한다. 같은 PC 시뮬레이터만 0초를 쓴다.
- 결과 unknown 뒤 FAULT 격리는 정상이다. 시험 도구가 이를 해제하거나 성공으로 바꾸지 않는다.
- 기존 open 공용형의 결과 재인계는 reserved_at 문맥 차이로 경고를 남길 수 있다. 범위 밖 수정 대신 `server/tools/node_lab/KNOWN_ISSUES.md`에 이슈 초안을 둔다.
- PlatformIO와 라이브러리 설치가 가능하면 보드 없이 컴파일한다. 물리 업로드·수신·GPIO는 미검증이다.
- USB 주입은 보드를 손에 쥔 사람만 한다고 가정한다. USB 접근 통제는 시험 환경의 물리 통제를 따른다. 운영 배포 방식은 정하지 않는다.
- 노트북 핫스팟 주소가 바뀌면 다시 주입한다. 주소 자동 탐색은 만들지 않는다.
- 시각원 응답의 동기화 품질은 lwIP SNTP의 응답 검사에 의존한다. 미동기화 응답 차단은 시각원 쪽에서 확인한다 (AGENTS Gotchas).
- 실제 기기 한 대로는 여러 기기의 동시 부팅, 기기 간 구분, 브로커 ACL 교차 거부를 실측하지 않는다.
