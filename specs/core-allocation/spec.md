# FR-23 전역 할당: 배정 알고리즘

- 상태: 작성 중
- 담당: eunji719 (판정)
- 요구사항: FR-23, FR-16, NFR-09
- 따르는 결정: 없음

## 1. 왜

- `any:locker` 요청이 여럿 겹치면 같은 사물함을 고르는 충돌이 난다. 요청을 하나씩 처리하면 먼저 온 요청이 사물함을 가져가서 전체 배정 수가 줄거나 근접이 나쁜 배정이 나온다.
- 배정 기준(최대 배정 수, 최소 비용, ID 순서)을 정하지 않으면 같은 입력에서 결과가 달라질 수 있다 (NFR-09).
- 대기 구간 모으기와 파이프라인 연결은 이 배정 함수가 있어야 만들 수 있다. 이 작업은 배정 함수만 다룬다.

## 2. 무엇

- 입력: 요청 목록. 요청마다 요청 ID와, 허용쌍을 이루는 기기별 근접 확률(다시 정규화하지 않은 사후확률)을 담는다.
- 출력: 요청 ID → 기기 ID. 배정받지 못한 요청은 담지 않는다.
- 바뀌는 상태: 없다. 순수 함수다. 저장소, 시계, 설정을 쓰지 않는다.
- 약속:
  - 한 기기는 요청 하나에만 배정한다. 입력에 없는 쌍은 배정하지 않는다.
  - 배정 기준의 우선순위는 아래와 같다 (FR-23).
    1. 배정 수를 최대화한다.
    2. 비용 `−log(근접확률)`의 합을 최소화한다.
    3. 요청 ID 오름차순으로 요청을 보고, 각 요청에 더 작은 기기 ID를 주는 배정을 고른다 (사전식 최소). 배정받는 쪽이 배정받지 못하는 쪽보다 앞선다.
  - 같은 입력은 입력 순서와 관계없이 같은 배정을 반환한다.

## 3. 제약

- 근접 확률을 다시 정규화하거나 임계값을 완화하지 않는다. 받은 값을 그대로 비용에 쓴다 (FR-16, FR-23).
- 임계값, 정책, 점유 조건으로 허용쌍을 거르는 일은 호출자(판정)가 한다. 이 함수는 입력의 쌍을 모두 허용쌍으로 본다.
- 비용 비교의 부동소수점 오차는 `1e-9`까지 같은 값으로 본다. 같은 비용이면 3순위로 정한다.
- 입력이 틀리면 `ValueError`를 올린다. 거부 판정을 만들지 않는다. 판정 사유는 호출자가 정한다.
- 시간, 설정, 난수를 쓰지 않는다 (NFR-09).
- 다른 계층에 의존하지 않는다. `shared`도 바꾸지 않는다.

## 6. 결정

- 함수는 `core/allocation/allocator.py`의 `allocate(requests, max_nodes=20)` 하나다. 입력 모델 `AllocationRequest(request_id, candidates)`도 같은 파일에 둔다. 담당자가 정했다 — 배정은 CORE 내부 계산이라 `shared`에 계약을 늘리지 않는다.
- 알고리즘은 요청 ID 순으로 요청을 보며 사용한 기기 집합(bitmask)으로 상태를 나눈 동적 계획법이다. 담당자가 정했다 — 완전 탐색과 같은 최적해를 주면서 조합 폭발을 줄인다. 상태마다 (배정 수, 비용, 사전식 배정)을 비교한다.
- `max_nodes`는 후보 기기 수의 안전 상한이다. 담당자가 정했다 — 상태 수가 `2^기기 수`로 늘기 때문이다. 시연 규모(사물함 6대 이하)보다 충분히 크다.
- 동률 3순위의 해석은 요청 ID 오름차순 사전식 최소다. 담당자가 정했다 — 같은 입력이 항상 같은 배정을 낸다.

## 7. 가정

- 요청 ID는 `internal_request_id`다. 후속 spec에서 호출자가 이 값을 넘긴다.
- 허용쌍의 확률은 `0 < p ≤ 1`이다. 임계값 이상인지는 호출자가 보장한다.
- 지표 9의 "기준 최적해"는 이 spec의 테스트가 만든 완전 탐색 기준이다. 평가 스크립트(`tools/evaluation`)는 이 작업 밖이다.
