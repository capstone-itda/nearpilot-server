# 펌웨어 계약과 spec 작성 항목

이 폴더는 확정한 서버·펌웨어 계약과 펌웨어 spec에서 정할 내용을 구분해서 기록한다.
MQTT 연결 구현은 [게이트웨이 spec](../iot-mqtt-gateway/spec.md)이 맡는다.
IOT의 전체 분할은 [구현 계획](../iot-mqtt-gateway/plan.md)에 있다.

## 기준 문서

계약은 [제품](../../docs/product.md), [요구사항](../../docs/requirements.md), [아키텍처](../../docs/architecture.md)를 따른다.
문서의 권위 순서도 이 순서다. 닫힌 이슈와 PR 토론을 계약의 근거로 쓰지 않는다.
이 폴더는 펌웨어 구현 spec을 작성할 때 쓰는 참고 문서다. 구현과 실제 기기 검증은 아직 하지 않았다.
펌웨어 담당 배정은 architecture.md §2에서 미결이다.

## 확정한 계약

| 사안 | 현재 계약 | 근거 |
|---|---|---|
| 시각 신뢰 | 폐쇄망 시각원과 기기별 오차 실측을 쓴다. 검증 전 실행과 안전 확인을 차단한다 | requirements.md §1.2, architecture.md §5 MQTT 6절 |
| 반납 검사 | 사물함 v1은 `door_closed`·`locked`, 조명·스피커 v1은 `actuator_idle`을 요구한다 | architecture.md §4 반납 검사와 종료 |
| 실행 완료 | 물리 완료를 증명한 기능만 `succeeded`다. 관측 없는 IR 무드등은 `light_on=null`이다 | requirements.md FR-07, architecture.md §5 MQTT 5절 |
| 검사 오류 | 첫 구현은 확인 불능 경로를 유지한다. 측정하지 못한 bool을 만들거나 기존 결과를 덮어쓰지 않는다 | architecture.md §4 반납 검사와 종료, §5 MQTT 3절 |

## 펌웨어 spec에서 정할 내용

| 문서 | 담당자가 정할 내부 선택 | spec에 담을 검증 |
|---|---|---|
| [시각 동기화](clock.md) | 기존 폐쇄망 시각원에 연결하는 방법, 재동기화와 시각 신뢰 상태의 관리다 | 기기별 오차, 단절과 시계 보정, 검증 전 거부다 |
| [반납 근거](criteria.md) | 기존 v1 항목을 관측할 센서, 측정 절차와 이상 검출 방법이다 | 요청 뒤 새 측정, 필수 근거와 측정 실패 동작이다 |
| [실행 완료](completion.md) | 동작별 완료 관측, 명령 기록 저장과 재시작 복원 방법이다 | 물리 완료, 중복 구동 방지와 전원 차단 뒤 불명 보고다 |
| [검사 오류](check_errors.md) | 기존 v1 안에서 검사 기록과 오류 진단을 관리하는 방법이다 | 검사 ID 충돌, 미지원 기준과 불완전한 근거의 동작이다 |

담당자는 내부 선택을 구현 spec의 결정 절에 기록한다.
아직 고르지 않은 센서, 저장 방식이나 실측 수치를 이 문서에서 확정하지 않는다.
실제 기기의 검증 전에는 시뮬레이터 통과를 실제 기기의 검증 완료로 표시하지 않는다.

## 계약 변경의 경계

펌웨어 내부의 센서 선택, 측정 절차와 기록 저장 방식은 펌웨어 spec에서 정한다.
현재 docs가 미결로 둔 서버·공용 설정 이름과 적용 방법은 서버와의 연결 때 기존 계약 범위를 확인한다.
MQTT 필드, 검사 기준의 뜻, 공용 설정이나 다른 영역의 동작을 바꿔야 할 때만 팀 계약을 다룬다.

스피커의 새 보고 필드와 검사 오류 보고 확장은 현재 구현의 확정 범위에 넣지 않는다.
구체적인 필요가 확인되기 전에는 새 형식이나 새 기준 버전을 제안하지 않는다.
첫 구현은 docs의 MQTT v1과 확인 불능 동작을 따른다.
