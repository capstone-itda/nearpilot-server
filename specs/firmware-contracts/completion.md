## 질문

실제 기기의 동작별 완료 관측과 보고 필드를 무엇으로 확정하는가?

## 맥락

- 관련 영역: 펌웨어, IOT, 상태 관리, shared다.
- 관련 요구사항: FR-06, FR-07, NFR-10, NFR-14다.
- 입력: 사물함의 `open`, 조명과 스피커의 `on`·`off` 명령이다.
- 출력: 명령별 물리 완료 근거, 저장한 실행 결과와 필요한 보고 필드의 계약이다.
- 바뀌는 상태: 실제 기기에서 `succeeded`로 확인할 수 있는 기능의 범위다.
- 약속: PUBACK, `accepted`, `running`과 제어 신호 송출은 물리 완료의 근거가 아니다.
- 약속: 완료를 증명하지 못한 실행 결과는 `unknown`이다. 확인한 실행 실패는 `failed`다.
- 약속: IR 무드등의 관측 근거가 없으면 `light_on=null`이다. IR 송출만으로 성공을 보고하지 않는다.
- 약속: 현재 `physical_state`에는 스피커 재생 관측 필드가 없다.
- 약속: 접수 기록은 구동 전에 보존한다. 같은 `command_id`로 재접속·재부팅 뒤 다시 구동하지 않는다.
- 지금 정해야 하는 이유: 기능별 실제 완료 관측과 스피커의 보고 필드는 아직 미결이다.
- 근거: `docs/requirements.md` FR-06·FR-07·NFR-10과 `docs/architecture.md` §5 MQTT 3~5·7절이다.
- 추적: 기존 #142는 증명한 기능만 성공으로 보고하는 원칙을 정했다. 이번 이슈는 실제 관측과 보고 계약을 다룬다.

## 선택지

### A. 기능별 실제 관측을 검증하고 필요한 보고 필드를 계약한다

- 결과: 사물함 서보, LED 조명, IR 무드등과 스피커의 완료 관측을 각각 검증한다.
- 결과: 스피커의 재생·정지 확인 수단과 보고 필드를 함께 정한다.
- 결과: 기존 필드의 뜻을 바꾸는 변경은 스키마 버전을 올린다. 새 필드는 별도 계약으로 반영한다.

### B. 현재 관측 수단으로 증명한 기능만 먼저 제공한다

- 결과: 증명하지 못한 기능의 완료 검증 활성화는 후속 작업으로 남긴다.
- 결과: 관측 수단이 없는 기능을 가상 성공으로 대체하지 않는다.
- 결과: 스피커 보고 필드는 실제 관측 수단을 확인한 뒤 별도로 계약한다.

## 제안

기능별 관측 수단을 확인한 뒤 A의 계약을 정리하고, 제공 범위는 B처럼 검증한 기능부터 연다.
관측 표에 기기, 동작, 실제 완료 조건, 관측 수단, 오류 검출 범위와 보고 필드를 적는다.
실측하지 않은 센서 정확도와 완료 조건은 확정한 것으로 표시하지 않는다.

명령 도중 전원 차단, 완료 직전 전원 차단과 결과 저장 실패도 검증한다.
재시작 뒤 완료를 증명하지 못하면 `unknown`을 보고하고 같은 명령을 다시 구동하지 않는다.
실제 기기의 명령 기록 저장 방식과 결과 보존도 이 검증에서 확인한다.

반납 검사의 필수 근거 검증은 별도 사안이다. 명령 성공으로 반납 검사를 대신하지 않는다.
새 보고 형식은 팀 결정 뒤 MQTT·shared·IOT에 반영한다. 이번 이슈만으로 필드를 확정하지 않는다.
