# 펌웨어 spec의 반납 근거 항목

- 관련 요구사항: FR-07, FR-20, NFR-04, NFR-10이다.
- 근거: architecture.md §4 반납 검사와 종료, §5 MQTT 7절이다.

## 지킬 계약

| 기준 | v1의 필수 항목 |
|---|---|
| `locker-return` | `door_closed`, `locked`다 |
| `light-return` | `actuator_idle`이다 |
| `speaker-return` | `actuator_idle`이다 |

기기는 검사 요청을 받은 뒤 새로 측정한다.
`evidence`는 항목마다 bool인 `value`와 관측 시각 `observed_at`을 담는다.
필수 항목이 모두 참일 때만 `passed`다. 측정하지 못한 bool 값을 만들지 않는다.
일반 상태 보고와 명령 성공은 반납 검사를 대신하지 않는다. 점유 종료는 CORE가 결정한다.

## spec에서 정할 내용

| 항목 | 담당자가 기록할 내용 |
|---|---|
| 센서 대응 | 각 필수 항목을 어떤 실제 센서 관측으로 증명하는지 기록한다 |
| 측정 절차 | 요청을 받은 뒤 측정하는 순서와 관측 시각을 기록하는 방법이다 |
| 이상 검출 | 센서의 이상 검출 범위와 측정 실패를 식별하는 방법이다 |
| 근거 생성 | 관측을 기존 v1 항목의 bool 근거로 변환하는 방법이다 |

실제 센서의 증명 능력은 아직 검증하지 않았다.
리드 스위치의 문 닫힘 관측만으로 `locked`를 증명했다고 추정하지 않는다.
센서 선택과 측정 절차는 담당자가 구현 spec에서 정한다.

## spec에 담을 검증

1. 요청 뒤 새로 측정하고 검사 ID·대상 연결·기준을 결과와 연결하는지 확인한다.
2. 필수 항목별로 실제 관측과 관측 시각을 확인한다.
3. 유효한 근거가 참이면 `passed`, 거짓이면 `not_ready`인지를 확인한다.
4. 측정 실패를 거짓으로 채워 정상 대기로 만들지 않는지 확인한다.
5. 센서 이상과 필수 근거 누락을 통과로 보고하지 않는지 확인한다.

현재 v1을 증명하지 못하면 확인 불능 동작을 따른다.
새 기준 버전을 만드는 제안은 이 문서에 포함하지 않는다.
