## 질문

실제 기기는 반납 검사 v1의 필수 항목을 어떤 센서 근거로 증명하는가?

## 맥락

- 관련 영역: 펌웨어, IOT, 상태 관리, 기기 시뮬레이터다.
- 관련 요구사항: FR-07, FR-20, NFR-04, NFR-10이다.
- 입력: 검사 기준과 대상 연결을 지정한 `safety_check`다.
- 출력: 새로 측정한 검사 항목별 bool 값과 관측 시각을 담은 `safety_check_result`다.
- 바뀌는 상태: 실제 기기의 검사 결과를 CORE가 반납 종료의 근거로 쓸 수 있는지 여부다.
- 약속: `locker-return` v1은 `door_closed`와 `locked`를 요구한다.
- 약속: `light-return`과 `speaker-return` v1은 `actuator_idle`을 요구한다.
- 약속: `evidence`는 항목마다 `value`와 `observed_at`을 담는다. 모든 필수 항목이 참일 때만 `passed`다.
- 약속: 기기는 요청을 받은 뒤 새로 검사한다. 일반 상태 보고와 명령 성공은 반납 검사를 대신하지 않는다.
- 약속: 리드 스위치의 문 닫힘 관측만으로 잠금 상태를 증명했다고 추정하지 않는다.
- 지금 정해야 하는 이유: v1 기준은 통일했지만 실제 센서의 근거 제공 능력과 이상 검출 범위는 미검증이다.
- 근거: `docs/requirements.md` FR-07·FR-20·NFR-10과 `docs/architecture.md` §4 반납 검사와 종료, §5 MQTT 7절이다.
- 추적: 기존 #141은 v1 기준을 통일한 종결 이슈다. 이번 이슈는 실제 기기의 증명 능력을 다룬다.

## 선택지

### A. 현재 v1 항목을 실제로 증명하는 관측 수단을 검증한다

- 결과: 기기별 센서와 검사 항목의 대응, 관측 시점, 이상 검출 범위를 기록한다.
- 결과: 증명하지 못한 항목은 통과로 꾸미지 않는다. CORE는 확인 불능 경로를 유지한다.
- 결과: 센서 보완이 필요하면 하드웨어 변경 범위를 팀이 따로 결정한다.

### B. 실제 관측 능력에 맞춘 새 검사 기준을 계약한다

- 결과: v1 항목을 증명하지 못하는 기기는 기존 v1을 통과한 것으로 보고하지 않는다.
- 결과: 새 항목과 통과 조건을 별도 기준 버전으로 정한다.
- 결과: 기존 점유 세션은 생성 당시 기준을 유지한다. 새 기준을 과거 v1에 소급하지 않는다.

## 제안

A의 검증을 먼저 제안한다. 현재 하드웨어가 `locked`와 `actuator_idle`을 증명한다고 가정하지 않는다.
검증 표에 센서, 실제 관측, 검사 항목, 이상 검출 범위와 측정 실패 동작을 적는다.
리드 스위치의 문 닫힘 관측과 이상 검출 범위도 확인한다.

항목의 뜻이나 통과 조건을 바꿔야 하면 B를 별도 decision PR로 반영한다.
측정 실패를 `false`로 채워 정상 `not_ready`로 만들지 않는다.
필수 근거가 없는 결과는 현재 계약대로 확인 불능이다. 점유 종료는 CORE가 결정한다.
