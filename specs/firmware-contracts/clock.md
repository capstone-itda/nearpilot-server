## 질문

실제 기기의 폐쇄망 시각원을 어디에 두고 동기화 검증 결과를 어떤 설정 계약으로 전달하는가?

## 맥락

- 관련 영역: 펌웨어, IOT, 서버 조립, shared 설정이다.
- 관련 요구사항: FR-05, FR-06, FR-07, NFR-12다.
- 입력: 폐쇄망 시각원, 기기 관측 시각, 명령의 `issued_at`과 `expires_at`이다.
- 출력: 동기화 방식, 재동기화 간격, 기기별 최대 오차의 검증 근거와 설정 계약이다.
- 바뀌는 상태: 서버와 기기가 시각 기반 실행과 반납 검사를 허용할 수 있는지 여부다.
- 약속: 서버와 기기는 폐쇄망 시각원으로 동기화한다. 외부 인터넷을 필수로 두지 않는다.
- 약속: 최대 오차는 기기별 실측 뒤 설정한다. 검증 전 값은 미설정이다.
- 약속: 시각 신뢰를 확인하지 못하면 기기는 새 명령을 `CLOCK_UNVERIFIED`로 거부한다.
- 약속: 서버도 검증 전 기기의 시각 기반 실행과 안전 확인을 차단한다.
- 지금 정해야 하는 이유: 폐쇄망 동기화 원칙은 정했지만 실제 방식, 간격, 오차값과 설정 이름은 미결이다.
- 근거: `docs/requirements.md` §1.2와 `docs/architecture.md` §4 공동 인터페이스의 후속 반영, §5 MQTT 6·7절이다.
- 추적: 기존 #140은 원칙을 정한 종결 이슈다. 이번 이슈는 문서에 남은 실제 기기 검증과 설정 계약을 다룬다.

## 선택지

### A. 시연 노트북이 폐쇄망 시각원을 제공한다

- 결과: 기기는 독립 AP 안에서 노트북의 시각원에 동기화한다.
- 결과: 서버와 기기가 비교하는 UTC 시각, 오차 검증 방법과 재동기화 조건을 함께 정한다.
- 결과: 노트북의 시각 보정과 시각원 중단을 검증 범위에 넣는다.

### B. 폐쇄망의 별도 시각원이 서버와 기기를 동기화한다

- 결과: 별도 시각원의 운영과 장애 대응을 함께 정한다.
- 결과: 서버와 기기의 시각원 접근, UTC 시각과 최대 오차를 검증한다.
- 결과: 외부 인터넷 없이 같은 검증을 통과해야 한다.

## 제안

추가 시각원 없이 검증할 수 있으면 A를 제안한다. 실제 지원 여부는 설치 환경에서 확인한다.
동기화 방식과 주기는 검증 결과를 보고 정한다. 임의의 최대 오차와 기본값을 넣지 않는다.

검증에는 재부팅, 재접속, 장시간 동작, 시각원 단절과 시계 보정을 넣는다.
설정 계약에는 이름, 단위, 허용 범위, 적용 기기, 검증 근거와 검증 무효 조건을 담는다.
검증 실패와 미설정 상태는 실행 허용으로 바꾸지 않는다.

이번 이슈의 선택지는 제안이다. 실제 검증과 팀 결정 뒤 별도 decision PR로 문서와 공용 설정에 반영한다.
