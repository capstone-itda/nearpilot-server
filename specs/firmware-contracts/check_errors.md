## 질문

반납 검사의 오류 종류와 근거 부족을 구분하는 후속 보고 형식을 어떻게 계약하는가?

## 맥락

- 관련 영역: 펌웨어, IOT, 상태 관리, shared다.
- 관련 요구사항: FR-07, FR-20, NFR-04다.
- 입력: 같은 `check_id`의 다른 내용, 미지원 기준과 측정 불능이다.
- 출력: 오류 종류를 구분하고 원래 검사 결과를 보존하는 보고 계약이다.
- 바뀌는 상태: CORE가 오류를 구분하는 근거와 MQTT 결과의 유효성 검증 범위다.
- 약속: 첫 구현은 기존 v1의 확인 불능 경로를 유지한다.
- 약속: 같은 검사 ID의 다른 내용은 새로 검사하지 않는다. 기존 결과를 덮어쓰지 않는다.
- 약속: 측정하지 못한 bool 근거를 만들지 않는다. 필수 근거가 없으면 서버는 확인 불능으로 취급한다.
- 약속: 현재 실행 결과의 `RejectCode`를 검사 결과에 추가하는 계약은 없다.
- 지금 정해야 하는 이유: 검사 오류 코드, `unknown`·`fault`의 근거 예외와 오류 사건 ID 규칙은 후속 계약으로 남아 있다.
- 근거: `docs/requirements.md` FR-07과 `docs/architecture.md` §4 반납 검사와 종료, §5 MQTT 3절이다.
- 추적: 기존 #143은 v1의 확인 불능 동작을 정한 종결 이슈다. 이번 이슈는 문서에 남은 오류 보고 확장만 다룬다.

## 선택지

### A. 검사 결과의 새 버전에 오류 보고를 포함한다

- 결과: 오류 종류, 허용하는 근거의 형태와 필수 항목 예외를 함께 정한다.
- 결과: 오류 사건 ID, 재전송과 중복 판정 규칙도 함께 정한다.
- 결과: 기존 v1과 새 버전을 구분하고 MQTT·shared·IOT·CORE의 검증을 함께 맞춘다.

### B. 기존 v1을 유지하고 별도 진단 보고를 계약한다

- 결과: 반납 검사 결과의 필수 근거 규칙을 바꾸지 않는다.
- 결과: 별도 진단은 원래 검사와의 연결, 사건 ID와 중복 규칙을 갖는다.
- 결과: 진단만으로 검사 통과, 정상 대기나 점유 종료를 확정하지 않는다.

## 제안

오류를 검사 결과 안에서 구분해야 하면 A를 제안한다. 새 형식은 별도 decision PR로 확정한다.
어느 선택에서도 검사 ID 충돌이 기존 `passed`의 변경으로 정산되지 않게 한다.
오류 사건을 재전송할 때 같은 사건 ID와 내용을 보존하는 규칙을 정한다.

팀이 형식을 정하기 전까지 기존 v1의 확인 불능 경로로 구현할 수 있다.
이번 이슈는 첫 구현의 오류 보고 확장을 확정하거나 활성화하지 않는다.
