# 펌웨어 spec의 검사 오류 항목

- 관련 요구사항: FR-07, FR-20, NFR-04다.
- 근거: architecture.md §4 반납 검사와 종료, §5 MQTT 3절이다.

## 지킬 계약

첫 구현은 현재 v1의 확인 불능 경로를 따른다.
같은 `check_id`의 다른 내용은 새로 검사하지 않는다. 기존 검사 결과를 덮어쓰지 않는다.
기기는 측정하지 못한 bool 값을 만들지 않는다.
필수 근거가 없는 결과는 서버가 확인 불능으로 취급한다.
실행 결과의 `RejectCode`를 검사 결과에 추가하지 않는다.

## spec에서 정할 내용

| 항목 | 담당자가 기록할 내용 |
|---|---|
| 검사 기록 | 검사 ID와 기존 요청 내용·결과를 보관하고 대조하는 방법이다 |
| 충돌 대응 | 같은 ID의 다른 내용이 기존 검사와 결과를 바꾸지 못하게 하는 방법이다 |
| 측정 실패 | 미지원 기준과 센서 측정 실패를 식별하는 방법이다 |
| 내부 진단 | 자격정보와 임의의 본문 전체를 남기지 않고 원인을 기록하는 방법이다 |

내부 기록과 진단 방법은 담당자가 구현 spec에서 정한다.
새 오류 코드, 근거 예외, 진단 토픽이나 결과 버전은 제안하지 않는다.
실제 구현에서 외부 형식 변경이 필요해지면 그때 팀 계약의 범위를 확인한다.

## spec에 담을 검증

| 상황 | 확인할 동작 |
|---|---|
| 같은 검사 ID와 같은 요청이다 | 기존 검사 결과를 반환한다. 새 측정은 시작하지 않는다 |
| 같은 검사 ID의 내용이 다르다 | 새로 검사하거나 기존 결과를 덮어쓰지 않는다. 서버는 충돌 요청의 응답 기한 초과로 다룬다 |
| 기준을 지원하지 않거나 측정하지 못한다 | 통과와 거짓 bool을 만들지 않는다. 서버의 확인 불능 동작을 유지한다 |
| 유효한 근거로 고장을 확인했다 | 기존 `fault` 결과를 사용한다 |
| 결과를 다시 보고한다 | 기존 결과 사건 ID와 내용을 보존한다 |

기존 형식으로 첫 구현을 진행할 수 있다. 오류 보고 확장을 먼저 정할 필요는 없다.
