# 운영 대시보드 모니터 (목 데이터)

- 담당: dnnals (대시보드)
- 요구사항: FR-12A, FR-12B, NFR-12
- 따르는 결정: #168

## 1. 왜

- `dashboard/`가 비어 있다. 시연 관객과 운영자가 판정 흐름(누가 무엇을 요청했고, 서버가 무엇을 확인했고, 결과가 어떤지)을 볼 화면이 없다.
- 대시보드 조회 REST와 모니터링 WebSocket은 경로와 메시지 형식이 미결이다 (FR-12A, FR-12B). 서버 계약을 기다리면 화면 작업을 시작할 수 없다.

## 2. 무엇

- 입력: 데이터 소스(`DataSource`)가 주는 모니터링 이벤트 스트림(FR-12B)과 조회 결과(FR-12A). 이번 작업의 데이터 소스는 목 어댑터 하나다.
- 출력: 브라우저에서 여는 정적 웹 앱. 화면은 승인한 화면 설계 목업(15화면, 다크·라이트)과 같은 구조다.
  - 모니터: 상단 바, 폰 미러링(왼쪽), 무대(표시용 배치도), 흐름 레일
  - 패널(무대 위에 겹쳐 열림): 요청 상세, 기기 상세, 점유·대여 현황, 승인 현황, 감사 로그, 요청·판정 이력, 신뢰도 지표
  - 설정: 배치(끌어다 놓기 편집과 실시간 신호), 폰 연결, 점검
  - 연결 끊김 안내
- 바뀌는 상태: 서버 상태는 바꾸지 않는다. 이 PC의 표시 설정(테마, 미러링 창 연결, 자동 전환, 무대 배치)만 브라우저에 둔다. 무대 배치는 JSON 파일로 내보내고 불러온다.
- 약속:
  - 화면 코드는 `DataSource` 인터페이스에만 의존한다. 서버 계약이 정해지면 서버 어댑터만 더한다.
  - 대시보드는 받은 이벤트를 차례로 쌓아 모니터 상태를 만든다. 레일 문구, 무대의 흐름 선, 콜아웃, 흐리게 하기는 이 상태에서 규칙으로 계산한다. 장면별 고정 값을 두지 않는다.
  - 요청 하나가 이벤트로 들어오는 순서(AI 도구 호출 도착 → 판정 단계 ⓪~⑥ → 판정 → MQTT 명령 → 기기 결과 → AI에 응답)를 무대, 레일, 요청 상세가 따라 보인다.

## 3. 제약

- 대시보드는 서버에 쓰지 않는다. 쓰기 요청을 보내는 버튼과 코드가 없다 (FR-12A).
- 빌드 결과는 외부 네트워크 없이 동작한다. 글꼴과 모든 자산을 번들에 넣는다 (NFR-12).
- 사람은 이름(방문자 A, 소유자)으로만 보인다. 사용자 ID를 화면에 쓰지 않는다 (FR-11, NFR-08).
- 판정 값, 사유 코드, 단계, 상태 이름은 `server/src/nearpilot/shared/enums.py`에 있는 값만 쓴다.
- 설정값(임계값, 대여 시간)은 숫자를 지어내지 않고 데이터 소스에서 받거나 "설정값"으로 표시한다.
- 미결 항목(알림 수단, 평가 기준 등)은 "미결"로 표시한다.
- 무대는 실제 위치나 거리를 보이지 않는다. 서버는 기기 좌표와 사람 좌표를 주지 않는다 (FR-12A, FR-12B). 무대에 "표시용 배치"라고 적는다.

## 5. 예외 상황
| 상황 | 기대 동작 | 테스트 |
|---|---|---|
| 데이터 소스 연결이 끊김 | 마지막 화면을 유지하고 연결 끊김 안내와 마지막 수신 시각을 보인다. 점검 화면은 마지막으로 받은 결과라고 알린다 | `offline` 장면 e2e, 패널 e2e |
| 진행 중인 요청이 없음 | 대기 안내와 다섯 단계 설명을 보인다 | `idle` 장면 e2e, 레일 단위 |
| 판정이 ASK, NEED_APPROVAL, BUSY, DENY | 기기를 실행하지 않았다고 레일에 보이고, 멈춘 단계를 강조한다 | 레일 단위 |
| 실행 결과 불명·실패로 FAULT | 대상 기기를 고장 격리로 보이고 기기 상세와 요청 상세에 원인을 보인다. 복구 화면과 버튼은 없다 (복구는 소유자 스크립트) | `fault` 장면 e2e |
| 미러링 창이 없음 | 폰 자리에 "미러링 창 없음"을 보인다 | `PhoneMirror` 컴포넌트 단위 |
| 브라우저 저장소를 쓸 수 없음 | 기본 설정(다크, 자동 전환 켬)과 기본 배치로 동작한다 | 설정 단위 |
| 저장한 배치에 없는 기기가 오거나, 저장한 자리가 겹침 | 그 기기만 빈자리에 놓는다. 없어진 기기의 자리는 버린다 | 배치 단위 |
| 기기를 방 밖이나 다른 기기와 겹치는 자리에 놓음 | 놓지 않고 원래 자리로 돌린다 | 배치 단위, 배치 e2e |
| 형식이 틀리거나, 한 대라도 방 밖이나 겹치는 자리인 배치 파일을 불러옴 | 배치를 바꾸지 않고 이유를 보인다. 지금 장소에 없는 기기는 건너뛰고 수를 알린다 | 배치 단위, 배치 e2e |
| 1366×768 ~ 3840×2160 | 1920×1080 기준 비율로 확대·축소하고 넘침·겹침·가로 스크롤이 없다 | 해상도 e2e |

## 6. 결정

- React + Vite + TypeScript — 팀이 쓰는 웹 스택 중 정적 빌드가 가장 단순하다.
- 목업 CSS를 그대로 쓰고 상태는 `data-*` 속성으로 둔다 — 검증한 화면을 그대로 재현한다. 인라인 style을 쓰지 않는다.
- 글꼴은 `@fontsource` 패키지로 번들한다 — NFR-12.
- 데이터 소스는 이벤트 구독 하나와 조회 함수들로 나눈다 — FR-12B는 이벤트 스트림이고 FR-12A는 조회 REST다. 구독은 이벤트 묶음을 넘긴다. 서버 어댑터는 WebSocket 메시지 하나를 한 묶음으로 넘긴다.
- 이벤트를 쌓는 리듀서(`data/reduce.ts`) 하나가 모니터 상태를 만든다. 진행 중인 요청은 판정 전에도 상태에 있다. 아직 오지 않은 단계는 `pending`이다 — 단계별 진행을 보이려면 판정 결과만이 아니라 도착한 순서가 필요하다.
- 연결 상태는 서버 이벤트가 아니다. 어댑터가 `link` 이벤트로 넘긴다.
- 끝난 요청(AI에 응답했고 소유자 응답을 기다리는 승인 신청이 없음)은 마지막 수신 시각 기준으로 15초 남긴 뒤 내리고 대기 화면으로 돌아간다. 승인 신청이 만료되면 그때부터 잰다. 표시용 값이라 서버 설정이 아니다 — 결과를 읽을 시간을 주면서, 지난 요청이 다음 요청까지 무대를 차지하지 않게 한다.
- 무대는 요청의 이벤트를 따라 선을 바꾼다. 도구 호출이 도착하면 응답할 때까지 호스트→서버 선, 판정 전에는 비콘→서버 선, 명령을 보내면 서버→기기 선, 응답하면 3초 동안 서버→호스트 선을 그린다. 판정 전에는 콜아웃을 두지 않는다. 레일은 판정 전에 3단계를 `판정 중`인 지금 단계로 둔다(판정 게이지는 서버 상자에만 둔다 — 두 곳에 있으면 번잡하다). 판정이 나면 3단계에 결과 한 줄(`③ 근접에서 멈춤`, `모두 통과`, 단계 밖이면 사유)을 적는다. 요청 상세는 오지 않은 단계를 `기다림`, 판정 전 태그를 `판정 중`으로 보인다. 레일의 `요청 상세` 버튼으로 진행 중인 요청의 상세를 열면 이벤트가 오는 대로 바뀌고, 다음 요청이 오면 닫힌다. 판정이 OK이고 명령을 아직 보내지 않았으면 `허가`로, 명령 이벤트가 오면 `실행 중`과 명령 선으로 보인다.
- 서버의 판정은 무대의 서버 상자가 가장 잘 보이게 한다 (2026-10-16 사용자 결정). 서버 상자는 확인 네 칸(누구인지 ①, 어디 앞인지 ③, 정책 ④, 비었는지 ⑤⑥)과 판정 표시를 보인다. 판정 전에는 윗변의 판정 게이지가 차고, 판정이 나면 네 칸이 한 번에 채워지며, 멈춘 칸은 판정 색 굵은 글씨로, 상자 테두리와 표시는 판정 색으로 바뀐다. 레일의 3단계는 결과 한 줄만 둔다 — 관람자가 보는 무대에서 서버가 무엇을 확인했는지 읽히고, 같은 내용을 두 곳에 두지 않는다.
- 화면 문구는 짧게 쓴다 (2026-10-16 사용자 결정). 화면이 보이는 것을 다시 설명하는 문장(예: "아래 다섯 단계가 차례로 밝아져요", 콜아웃 둘째 줄의 같은 말)은 쓰지 않는다. 콜아웃 둘째 줄은 제목만으로 모자랄 때만 둔다.
- 판정은 실제 시간대로 보이고, 1초짜리 판정 게이지만 둔다 (2026-10-16 사용자 결정). 도구 호출이 오면 요청 점이 서버에 닿고(0.6초) 게이지가 차는(1초) 동안 그 뒤 이벤트를 모았다가 순서대로 넘긴다. RSSI, 비콘, 연결 이벤트는 바로 넘긴다. 같은 묶음에 판정까지 있으면(다시 연결해 받은 지금 상태) 늦추지 않는다. 게이지 시간은 표시용 값이라 서버 설정이 아니다 — 단계를 하나씩 보이는 연출 없이도, 요청이 도착해 판정되는 순간을 눈이 따라가고 어디서 멈췄는지는 결과에서 바로 읽힌다.
- 화면은 모니터 상태에서 순수 함수로 계산한다 — 서버 어댑터를 붙여도 화면 로직을 다시 쓰지 않는다.
- 판정이 ASK, NEED_APPROVAL이거나 기기가 새로 FAULT가 되면 해당 상세 패널을 자동으로 연다. 메뉴로 연 목록 패널(점유, 승인, 감사, 이력, 신뢰도)이 열려 있으면 바꾸지 않는다. ×로 닫는다.
- 상단 바에 마지막 이벤트 수신 시각을 보인다 — 스트림이 들어오는 것을 화면 어디서나 알아볼 수 있게 한다.
- 무대는 표시용 배치도다. 기기 자리는 설정의 배치 화면에서 끌어다 놓거나 화살표 키로 정한다. 방 사각형 안에서 24 단위 격자에 맞추고, 기기끼리 겹치지 않게 한다 — 서버가 좌표를 주지 않고, 시연 장소를 화면에 맞게 그리려면 사람이 정해야 한다.
- 배치는 이 PC 브라우저에 장소별로 저장하고 JSON 파일로 내보내고 불러온다. 저장한 배치가 없으면 대여형은 위쪽, 공용형은 아래쪽 줄에 자동으로 놓는다 — 서버에 쓰지 않으면서(FR-12A) 시연 PC를 바꿔도 되살린다.
- 무대의 사람, 이름표, 콜아웃은 기기 글자와 다른 사람을 피해 방 안의 빈자리를 격자로 찾아 놓는다 — 배치를 사람이 바꾸므로 고정 좌표로는 겹침을 막을 수 없다.
- 관람자의 시선을 이끈다 (2026-10-16 사용자 결정). 흐름 선이 켜지면 메시지 점이 출발지에서 도착지까지 0.6초 동안 이동한다. 그동안 메시지를 받는 쪽(서버, 기기, 소유자 폰)의 바뀐 표시와 콜아웃, 레일의 지금 단계, 폰 화면은 흐리게 있다가, 점이 도착하면 나타나며 한 번 빛난다. 보내는 쪽(AI 호스트)과 지난 단계는 강조하지 않는다 — 한 번에 볼 곳을 줄인다. 처음 그린 화면과 움직임 줄이기 설정에서는 하지 않는다 — 이미 바뀐 상태를 뒤늦게 찾는 대신, 움직임을 따라 원인에서 결과로 눈이 간다.
- 대기 장면의 비콘 안내 콜아웃은 글자를 가리지 않는 자리가 있을 때만 보인다 — 안내용이라 가리면서까지 보일 필요가 없다.
- 패널이 열려 있으면 콜아웃은 패널 왼쪽에만 둔다. 넓은 패널(감사, 이력, 신뢰도)이 열렸거나, 글자와 겹치지 않고 지시선이 기기 글자를 지나지 않는 자리가 없으면 콜아웃을 숨긴다 — 패널이 같은 내용을 보이고, 가린 콜아웃은 읽을 수 없다.
- 패널의 조회는 모니터 상태의 요청, 판정, 실행 결과, 승인, 기기 상태, 비콘 수신, 연결, 분 단위 수신 시각이 바뀌면 다시 부른다. 다시 부르는 동안 지금 결과를 둔다. 신호 세기만 바뀌면 다시 부르지 않는다 — 판정 흐름과 패널이 어긋나지 않게 하면서 조회를 줄인다.
- 무대의 사람 자리는 표시용으로 고른다. 요청한 사람은 판정이 고른 기기 앞, ASK면 확률이 높은 두 기기 사이, 그 밖에는 신호가 가장 센 기기 앞에 둔다. 다른 기기의 신호가 지금 기기보다 4dB 이상 센 상태가 2초 이어질 때만 옮기고, 옮길 때는 0.6초 동안 미끄러진다 (2026-10-16 사용자 결정) — RSSI가 흔들려도 점이 두 기기 앞을 오가지 않고, 순간 이동 대신 눈이 따라간다. 두 값은 표시용이라 서버 설정이 아니다. 실제 위치를 추적하지 않는다. 판정에는 쓰지 않는다 — 서버는 사람 좌표 대신 후보 확률과 RSSI를 준다 (FR-12B).
- 목 어댑터는 시각이 붙은 이벤트 이야기(`data/mock/story.ts`) 하나를 가진다. 고정 장면(`?scene=`)은 그 장면 시각까지의 이벤트를 연결 직후 한꺼번에 보낸 결과다. 조회 결과는 마지막으로 보낸 이벤트 시각까지 생긴 기록만 준다. 이력과 신뢰도 집계는 AI에 응답한 뒤, 감사 로그 줄은 그 줄의 이벤트가 온 뒤에 보인다. 신뢰도의 실시간 판정 수는 시연 세션 시작부터 그 시각까지의 이력 수와 같고, 승인·대여 조회에 나온 사용은 이력에도 있고, 점검의 비콘 수신은 모니터 상태를 따른다 — 장면과 패널이 같은 시각을 보이게 한다.
- 목 어댑터는 `?scene=`으로 장면을 고정한다. 값이 없으면 대기 장면이다. `?scene=play`는 장면을 차례로 한 번 재생한다. 처음으로 돌아가면 고장 격리가 복구 없이 풀린 것처럼 보이기 때문이다.
- 목 어댑터의 `?scene=live`는 이벤트 이야기를 시각 순서대로 보낸다. 판정 이벤트는 실제처럼 0.2초 안에 보내고, 명령 뒤 결과를 기다리는 간격은 2초 이상으로 늘리고, 이벤트 사이의 조용한 구간은 빨리 감는다. 비콘 신호 세기는 0.5초마다 보낸다. 이야기가 끝나면 실제 속도로 계속 간다 — 서버 없이도 이벤트가 도착하는 순서대로 화면이 바뀌는 흐름을 보인다. 상단 바에 목 데이터라고 적는다.
- 목 어댑터는 사람마다 가짜 폰 화면을 목 전용 이벤트(`mock_phone`)로 준다. 미러링 창이 없을 때 이 화면을 보인다. 서버 어댑터는 이 필드를 비우고 미러링 영상만 쓴다.
- 테스트는 Vitest(계산·컴포넌트)와 Playwright(장면별 해상도·넘침·대비)로 한다.

## 7. 가정

- FR-12B 이벤트는 `src/model/events.ts`의 종류로 온다: 도구 호출 도착(`mcp_call`)과 응답(`mcp_result`), 판정 단계(`step`), 후보 확률(`posterior`), 판정(`verdict`), 기기 상태 전이(`transition`, FAULT 원인 포함), MQTT 명령(`command`)과 실행 결과(`exec_result`), 승인 신청과 결정(`approval`), 비콘 수신(`beacon`, 이름 포함)과 RSSI(`rssi`), 감사 로그(`audit`). 모든 이벤트에 서버 시각이 붙는다 — 미결: FR-12B 메시지 형식 (이슈 없음)
- 연결하면 서버가 진행 중인 요청과 지금 상태를 이벤트로 다시 보낸다 — 미결: FR-12B 메시지 형식 (이슈 없음)
- 사람 이름(`방문자 A`, `방문자 B`)과 글자는 서버가 붙여 비콘 이벤트와 조회 REST에 같게 준다 (architecture.md §5). 이름을 유지하는 기간은 미결: FR-12B 메시지 형식 (이슈 없음)
- 조회 REST의 장소 정보는 장소 이름, 근접 모델 버전, 기기 목록(이름, 기능, 점유 방식), 배치 화면의 약한 신호 기준(dBm)을 담는다. 좌표는 없다 — 미결: FR-12A 조회 REST 형식 (이슈 없음)
