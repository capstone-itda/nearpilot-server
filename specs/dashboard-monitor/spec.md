# 운영 대시보드 모니터 (목 데이터)

- 담당: dnnals (대시보드)
- 요구사항: FR-12A, FR-12B, NFR-10, NFR-12
- 따르는 결정: #168

## 1. 왜

- `dashboard/`가 비어 있다. 시연 관객과 운영자가 판정 흐름(누가 무엇을 요청했고, 서버가 무엇을 확인했고, 결과가 어떤지)을 볼 화면이 없다.
- 대시보드 조회 REST와 모니터링 WebSocket을 쓰는 서버 어댑터가 없다 (FR-12A, FR-12B). 서버를 기다리면 화면 작업을 시작할 수 없다.
- 시연 장소는 둘이다 (NFR-10: 사물함·조명·스피커의 장소, 무드등의 두 번째 장소). 무대가 장소 하나만 그리면 두 번째 장소의 요청과 사람이 보이지 않는다.

## 2. 무엇

- 입력: 데이터 소스(`DataSource`)가 주는 모니터링 이벤트 스트림(FR-12B)과 조회 결과(FR-12A). 데이터 소스는 목 어댑터와 서버 어댑터 둘이다. 주소의 `?source=server`이면 서버 어댑터를 쓴다.
- 출력: 브라우저에서 여는 정적 웹 앱. 화면은 승인한 화면 설계 목업(15화면, 다크·라이트)과 같은 구조다.
  - 모니터: 상단 바, 폰 미러링(왼쪽), 무대(표시용 배치도), 사이드 메뉴(오른쪽 끝), 흐름 레일
  - 무대의 장소: 주 장소를 크게 그리고, 다른 장소에 사람이 있으면 무대 귀퉁이에 작은 방으로 그린다. 사람이 장소를 옮기거나 다른 장소에 요청이 오면 주 장소가 바뀐다. 상단 바의 장소 고르기로 주 장소를 고정한다.
  - 패널(무대 위에 겹쳐 열림): 요청 상세, 기기 상세, 점유·대여 현황, 승인 현황, 감사 로그, 요청·판정 이력, 신뢰도 지표
  - 설정(위쪽 탭): 배치(끌어다 놓기 편집과 실시간 신호), 폰 연결, 점검
  - 연결 끊김 안내
- 바뀌는 상태: 서버 상태는 바꾸지 않는다. 이 PC의 표시 설정(테마, 미러링 창 연결, 자동 전환, 무대 배치)과 서버 어댑터의 소유자 토큰(이 탭의 세션 저장소)만 브라우저에 둔다. 무대 배치는 JSON 파일로 내보내고 불러온다.
- 약속:
  - 화면 코드는 `DataSource` 인터페이스에만 의존한다. 서버 계약이 정해지면 서버 어댑터만 더한다.
  - 대시보드는 받은 이벤트를 차례로 쌓아 모니터 상태를 만든다. 레일 문구, 무대의 흐름 선, 콜아웃, 흐리게 하기는 이 상태에서 규칙으로 계산한다. 장면별 고정 값을 두지 않는다.
  - 요청 하나가 이벤트로 들어오는 순서(AI 도구 호출 도착 → 판정 단계 ⓪~⑥ → 판정 → MQTT 명령 → 기기 결과 → AI에 응답)를 무대, 레일, 요청 상세가 따라 보인다.

## 3. 제약

- 대시보드는 서버에 쓰지 않는다. 쓰기 요청을 보내는 버튼과 코드가 없다 (FR-12A).
- 빌드 결과는 외부 네트워크 없이 동작한다. 글꼴과 모든 자산을 번들에 넣는다 (NFR-12).
- 사람은 이름(방문자 A, 소유자)으로만 보인다. 사용자 ID를 화면에 쓰지 않는다 (FR-11, NFR-08).
- 판정 값, 사유 코드, 단계, 상태 이름은 `server/src/nearpilot/shared/enums.py`에 있는 값만 쓴다.
- 설정값(임계값, 대여 시간)은 숫자를 지어내지 않고 데이터 소스에서 받거나 "설정값"으로 표시한다.
- 미결 항목(알림 수단, 평가 기준 등)은 "미결"로 표시한다.
- 무대는 실제 위치나 거리를 보이지 않는다. 서버는 기기 좌표와 사람 좌표를 주지 않는다 (FR-12A, FR-12B). 무대에 "표시용 배치"라고 적는다.

## 4. 경계

### 고치는 곳
- `dashboard/`
- `docs/architecture.md`: §2 대시보드 담당, §5 WebSocket의 사람 이름, §8 기술 스택 (2026-10-16 사용자 결정)

### 고치지 않는 곳
- 항상: `docs/` (위 architecture.md 세 곳은 제외), `AGENTS.md` (Gotchas 절은 제외), `server/src/nearpilot/shared/`, `server/pyproject.toml`, `.github/`
- 이 작업: `server/` 전부 (서버 쪽 조회 서비스, 발행, 조립은 `feat/core-dashboard-queries`가 만든다)

### 다른 영역과 닿는 곳
| 계약 | 사용 또는 제공 | 상대 영역 |
|---|---|---|
| 대시보드 조회 REST (architecture.md §5 "대시보드 조회") | 사용 (서버 어댑터) | API |
| 모니터링 WebSocket (architecture.md §5 "WebSocket") | 사용 (서버 어댑터) | API |

### 만들지 않는 것
- 대시보드를 서버가 직접 내보내는 일. 대시보드는 Vite 개발·미리보기 서버로 열고, 그 서버가 `/dashboard/...`를 NearPilot 서버로 넘긴다.
- 서버의 `api/rest/`, `api/ws/`
- CI 작업. `.github/`는 고치지 않는다. 테스트는 로컬에서 실행한다.

## 5. 예외 상황
| 상황 | 기대 동작 | 테스트 |
|---|---|---|
| 데이터 소스 연결이 끊김 | 마지막 화면을 유지하고 연결 끊김 안내와 마지막 수신 시각을 보인다. 점검 화면은 마지막으로 받은 결과라고 알린다 | `offline` 장면 e2e, 패널 e2e |
| 진행 중인 요청이 없음 | 대기 안내와 다섯 단계 설명을 보인다 | `idle` 장면 e2e, 레일 단위 |
| 판정이 ASK, NEED_APPROVAL, BUSY, DENY | 기기를 실행하지 않았다고 레일에 보이고, 멈춘 단계를 강조한다 | 레일 단위 |
| 실행 결과 불명·실패로 FAULT | 대상 기기를 고장 격리로 보이고 기기 상세와 요청 상세에 원인을 보인다. 복구 화면과 버튼은 없다 (복구는 소유자 스크립트) | `fault` 장면 e2e |
| 미러링 창이 없음 | 폰 자리에 "미러링 창 없음"을 보인다 | `PhoneMirror` 컴포넌트 단위 |
| 미러링 창이 검은 화면만 보냄 (폰을 뽑았거나 폰 화면이 꺼짐) | 영상이 2초 넘게 모두 검으면 폰 자리에 "폰 화면 신호 없음"과 확인할 것(폰 USB 연결, 폰 화면 켜짐)을 보이고, 화면이 다시 들어오면 영상으로 돌아온다 | 미러링 단위, 미러링 신호 e2e |
| 미러링 창 공유가 실패함 | 사람이 공유 창에서 취소했으면 아무것도 보이지 않는다. 운영체제가 막았으면 화면 공유 권한 안내를 띄운다. 고른 화면을 잡지 못했거나 이 브라우저·주소에서 쓸 수 없으면 그 사람 카드에 이유와 할 일을 보이고, 다시 고르면 지운다 | 미러링 단위, 미러링 권한 e2e |
| macOS에서 이 PC가 미러링에 처음 성공하기 전 | 공유 창보다 화면 공유 권한 안내를 먼저 띄운다. 공유 창이 열린 채 운영체제 권한 창이 뜨면 공유 창을 닫을 때까지 권한 창이 화면을 덮기 때문이다 | 미러링 권한 e2e |
| 브라우저 저장소를 쓸 수 없음 | 기본 설정(다크, 자동 전환 켬)과 기본 배치로 동작한다 | 설정 단위 |
| 저장한 배치에 없는 기기가 오거나, 저장한 자리가 겹침 | 그 기기만 빈자리에 놓는다. 없어진 기기의 자리는 버린다 | 배치 단위 |
| 기기를 방 밖이나 다른 기기와 겹치는 자리에 놓음 | 놓지 않고 원래 자리로 돌린다 | 배치 단위, 배치 e2e |
| 형식이 틀리거나, 한 대라도 방 밖이나 겹치는 자리인 배치 파일을 불러옴 | 배치를 바꾸지 않고 이유를 보인다. 지금 장소에 없는 기기는 건너뛰고 수를 알린다 | 배치 단위, 배치 e2e |
| 사람이 다른 장소의 기기 앞으로 옮김 (요청 없음) | 무대에 세우는 기기(`near`)가 그 장소로 바뀌면 주 장소를 그 장소로 바꾼다. 앞 장소에 남은 사람이 있으면 작은 방으로 그린다 | 장소 단위, 앱 단위 |
| 비콘이 끊겼다가 같은 장소로 돌아옴 | 옮긴 것으로 보지 않는다. 사람의 장소는 비콘이 끊겨도 마지막 장소를 기억한다 | 장소 단위 |
| 무대에 세운 기기의 신호가 한 묶음에서 빠짐 (빈 묶음 포함) | 바로 옮기지 않는다. 다른 기기가 2초 이어 가장 세면 옮긴다 (장소가 오가지 않는다) | 리듀서 단위 |
| 화면을 새로 엶 | 진행 중인 요청의 장소, 없으면 사람이 있는 첫 장소, 없으면 첫 장소를 주 장소로 둔다. 처음 본 사람들을 옮긴 사람으로 보지 않는다 | 장소 단위 |
| 다른 장소의 기기에 요청이 옴 | 주 장소를 요청 장소로 바로 바꾼다. 요청 장소는 대상 기기, 요청한 사람의 장소, 후보 확률·판정의 기기 순서로 정한다. 정할 수 없으면(원격 요청) 바꾸지 않는다 | 장소 단위 |
| 두 장소에 사람이 따로 있음 | 주 장소는 크게, 다른 장소는 작은 방(장소 이름, 기기 상태 색, 사람 글자)으로 그린다. 한 사람은 자기 장소에만 그린다. 작은 방을 누르면 그 장소로 고정한다. 큰 무대의 방과 글자를 피할 자리가 없으면 작은 방을 그리지 않는다 | 장소 단위, 작은 방 단위, 두 장소 e2e |
| 장소를 고정함 | 사람 이동과 요청으로 주 장소를 바꾸지 않는다. 다른 장소에 사람이 있으면 작은 방으로 그린다. 장소 고르기의 자동을 누르면 풀린다 | 장소 단위, 상단 바 단위, 두 장소 e2e |
| 장소를 고정한 채 다른 장소에 요청이 옴 | 호스트·서버 선과 서버의 판정은 그린다. 기기로 가는 명령 선, 격리 선, 기기 콜아웃은 그리지 않고, 콜아웃은 작은 방(없으면 서버 랙)을 가리킨다. 요청한 사람이 다른 장소에 있으면 비콘→서버 선을 그리지 않는다. 이 장소의 기기는 요청과 관계없는 기기라서 강조하거나 흐리게 하지 않고, 패널이 열려도 방을 밀지 않는다 | 무대 단위 |
| 고정을 풂 (장소 고르기의 자동) | 진행 중인 요청의 장소, 없으면 고정한 동안에도 기억한 마지막 이동·요청의 장소로 돌아간다 | 장소 단위 |
| 패널이 열림 | 작은 방을 숨긴다 (패널이 무대 오른쪽을 덮는다) | 무대 단위 |
| 장소 목록이 비었음 | 무대와 배치 화면에 장소가 없다고 보이고 나머지 화면은 그대로 둔다 | 장소 단위, 앱 단위 |
| 서버 어댑터: 소유자 토큰이 없음 | 토큰 입력 화면을 보인다. 토큰은 이 탭의 세션 저장소에만 두고 주소와 화면에 쓰지 않는다 | 서버 어댑터 단위, 서버 어댑터 e2e |
| 서버 어댑터: 토큰이 틀렸거나 소유자가 아님 (REST 401·403, 스트림 4401·4403) | 다시 연결하지 않고 토큰을 지운 뒤 입력 화면에 이유를 보인다 | 서버 어댑터 단위 |
| 서버 어댑터: 스트림이 끊김, 서버 오류(1011), 대기열 넘침(1013), 인증 기한(4408) | 연결 끊김을 알리고(`link`) 다시 연결한다. 다시 연결하면 끊기기 전의 진행 중 요청과 소유자 알림을 지우고, 서버가 보낸 지금 상태로 이어 간다 — 끊긴 동안 끝난 요청과 승인 신청이 남지 않는다 | 서버 어댑터 단위 |
| 서버 어댑터: 메시지 형식이 틀림 (`v`가 다름, JSON이 아님, 모르는 이벤트) | 그 메시지나 이벤트만 버린다. `v`가 다르면 연결을 끊고 저절로 다시 연결하지 않는다. 끊김 띠의 "다시 연결"을 누르면 새로 연결한다 | 서버 어댑터 단위 |
| 서버 어댑터: 처음 장소 조회가 실패함 (서버에 닿지 못함, 서버 오류) | "불러오는 중"에 멈추지 않고 실패 이유와 "다시 시도"를 보인다. 누르면 장소 조회를 다시 한다 | 서버 어댑터 e2e |
| 서버 어댑터: 평가 리포트가 없음 (`evaluation` 없음) | 신뢰도 패널의 사전 평가 칸에 "평가 리포트 없음"을 보인다 | 신뢰도 패널 단위 |
| 1366×768 ~ 3840×2160 | 1920×1080 기준 비율로 확대·축소하고 넘침·겹침·가로 스크롤이 없다 | 해상도 e2e |

## 6. 결정

- React + Vite + TypeScript — 팀이 쓰는 웹 스택 중 정적 빌드가 가장 단순하다.
- 화면 구조는 목업을 따르고, 상태는 `data-*` 속성으로 둔다. 인라인 style을 쓰지 않는다 — 검증한 화면 구조를 재현하면서 상태를 CSS 규칙으로 바꾼다.
- 화면 톤은 iso-glow 헤어라인으로 한다 (2026-10-22 사용자 결정). 흑연색 판에 가는 선을 쓰고, 살아 있는 것(켜진 기기, 지나가는 신호, 판정 결과, 레일의 지금 단계)만 빛나게 한다. 강조색은 청록 하나이고, 판정 색 다섯(허가, 다시 질문, 승인 필요, 바쁨, 거부)은 색상을 그대로 둔다. 라이트 테마는 빛 번짐 없이 같은 색을 평평하게 칠하고, 바뀐 바탕에서 글자 대비를 맞추려고 판정 색과 강조색을 조금 어둡게 한다. 설정 화면의 탭 줄에 출처 링크(Made with ISO-GLOW, MIT)를 둔다 — 관람자가 무엇이 지금 움직이는지 한눈에 보고, 판정 결과는 색으로 바로 구분한다.
- 무대는 평면 배치를 아이소메트릭으로 투영해 그린다 (`view/iso.ts`, 2026-10-22 사용자 결정). 방은 바닥판과 뒤쪽 낮은 벽, 기기는 기능별 상자(사물함, 스피커, 받침 위 조명), 사람은 바닥 고리와 기둥 위의 글자 머리, 서버는 확인 네 칸마다 불이 하나씩 있는 랙이다. 투영 각은 30°가 아니라 20°로 눕히고, 방을 서버 높이에 맞춰 내려 아래 여백을 줄인다 (2026-10-23 사용자 결정, 30°에서는 바닥이 쏟아질 듯 기울어 보였다). 배치 좌표, 격자, 겹침 규칙은 평면 그대로 두고, 배치 화면에서 끄는 자리는 바닥 평면으로 되돌려 격자에 맞춘다. 무대의 기기 글자는 이름과 상태 두 줄이고 기기 코드는 기기 상세에만 둔다 — 배치 파일과 규칙을 바꾸지 않고 그림만 바꾼다.
- 글꼴은 `@fontsource` 패키지로 번들한다 — NFR-12.
- 데이터 소스는 이벤트 구독 하나와 조회 함수들로 나눈다 — FR-12B는 이벤트 스트림이고 FR-12A는 조회 REST다. 구독은 이벤트 묶음을 넘긴다. 서버 어댑터는 WebSocket 메시지 하나를 한 묶음으로 넘긴다.
- 이벤트를 쌓는 리듀서(`data/reduce.ts`) 하나가 모니터 상태를 만든다. 진행 중인 요청은 판정 전에도 상태에 있다. 아직 오지 않은 단계는 `pending`이다 — 단계별 진행을 보이려면 판정 결과만이 아니라 도착한 순서가 필요하다.
- 연결 상태는 서버 이벤트가 아니다. 어댑터가 `link` 이벤트로 넘긴다.
- 끝난 요청(AI에 응답했고 소유자 응답을 기다리는 승인 신청이 없음)은 마지막 수신 시각 기준으로 15초 남긴 뒤 내리고 대기 화면으로 돌아간다. 승인 신청이 만료되면 그때부터 잰다. 표시용 값이라 서버 설정이 아니다 — 결과를 읽을 시간을 주면서, 지난 요청이 다음 요청까지 무대를 차지하지 않게 한다.
- 무대는 요청의 이벤트를 따라 선을 바꾼다. 도구 호출이 도착하면 응답할 때까지 호스트→서버 선, 판정 전에는 비콘→서버 선(요청한 사람이 다른 장소에 있으면 이 무대에는 그 선과 그 사람의 신호 세기를 그리지 않는다 — 그 사람은 작은 방에 있다), 명령을 보내면 서버→기기 선, 응답하면 3초 동안 서버→호스트 선을 그린다. 판정 전에는 콜아웃을 두지 않는다. 레일은 판정 전에 3단계를 `판정 중`인 지금 단계로 둔다(판정 게이지는 서버 랙에만 둔다 — 두 곳에 있으면 번잡하다). 판정이 나면 3단계에 결과 한 줄(`③ 근접에서 멈춤`, `모두 통과`, 단계 밖이면 사유)을 적는다. 요청 상세는 오지 않은 단계를 `기다림`, 판정 전 태그를 `판정 중`으로 보인다. 레일의 `요청 상세` 버튼으로 진행 중인 요청의 상세를 열면 이벤트가 오는 대로 바뀌고, 다음 요청이 오면 닫힌다. 판정이 OK이고 명령을 아직 보내지 않았으면 `허가`로, 명령 이벤트가 오면 `실행 중`과 명령 선으로 보인다.
- AI 호스트의 종류(Claude, ChatGPT, Gemini)는 구분하지 않는다 (2026-10-21 사용자 결정). 무대에는 AI 호스트 상자 하나를 두고, 레일·요청 상세·이력에 호스트 이름을 쓰지 않으며, 이력의 AI 거르기와 점검의 AI 호스트 칸(`tools/list` 기록)을 두지 않는다 — 서버가 호스트 종류와 `tools/list` 기록을 갖고 있지 않고, 관람자가 흐름을 따라가는 데 필요하지 않다.
- 서버의 판정은 무대의 서버 랙이 가장 잘 보이게 한다 (2026-10-16 사용자 결정). 서버는 랙으로 그리고, 옆에 확인 네 줄(누구인지 ①, 어디 앞인지 ③, 정책 ④, 비었는지 ⑤⑥)과 판정 표시를 둔다. 랙 앞면에는 네 줄마다 불이 하나씩 있다. 판정 전에는 앞면 위쪽의 판정 게이지가 차고, 판정이 나면 네 줄과 불이 한 번에 채워지며, 멈춘 줄은 판정 색 굵은 글씨로, 랙 테두리와 표시는 판정 색으로 바뀐다. 레일의 3단계는 결과 한 줄만 둔다 — 관람자가 보는 무대에서 서버가 무엇을 확인했는지 읽히고, 같은 내용을 두 곳에 두지 않는다.
- 화면 문구는 짧게 쓴다 (2026-10-16 사용자 결정). 화면이 보이는 것을 다시 설명하는 문장(예: "아래 다섯 단계가 차례로 밝아져요", 콜아웃 둘째 줄의 같은 말)은 쓰지 않는다. 콜아웃 둘째 줄은 제목만으로 모자랄 때만 둔다.
- 판정은 실제 시간대로 보이고, 1초짜리 판정 게이지만 둔다 (2026-10-16 사용자 결정). 도구 호출이 오면 요청 점이 서버에 닿고(0.6초) 게이지가 차는(1초) 동안 그 뒤 이벤트를 모았다가 순서대로 넘긴다. RSSI, 비콘, 연결 이벤트는 바로 넘긴다. 같은 묶음에 판정까지 있으면(다시 연결해 받은 지금 상태) 늦추지 않는다. 게이지가 도는 중에 다시 연결되면 모아 둔 이벤트를 버린다 — 아직 진행 중인 것은 지금 상태가 다시 보낸다. 게이지 시간은 표시용 값이라 서버 설정이 아니다 — 단계를 하나씩 보이는 연출 없이도, 요청이 도착해 판정되는 순간을 눈이 따라가고 어디서 멈췄는지는 결과에서 바로 읽힌다.
- 화면은 모니터 상태에서 순수 함수로 계산한다 — 서버 어댑터를 붙여도 화면 로직을 다시 쓰지 않는다. 예외는 주 장소다. 앞 계산을 함께 넘긴다 (아래 장소 결정).
- 판정이 ASK, NEED_APPROVAL이거나 기기가 새로 FAULT가 되면 해당 상세 패널을 자동으로 연다. 사이드 메뉴로 연 목록 패널(점유, 승인, 감사, 이력, 신뢰도)이 열려 있으면 바꾸지 않는다. ×로 닫는다.
- 상단 바에 마지막 이벤트 수신 시각을 보인다 — 스트림이 들어오는 것을 화면 어디서나 알아볼 수 있게 한다.
- 무대는 표시용 배치도다. 기기 자리는 설정의 배치 화면에서 끌어다 놓거나 화살표 키로 정한다. 방 사각형 안에서 24 단위 격자에 맞추고, 기기끼리 겹치지 않게 한다 — 서버가 좌표를 주지 않고, 시연 장소를 화면에 맞게 그리려면 사람이 정해야 한다.
- 배치는 이 PC 브라우저에 장소별로 저장하고 JSON 파일로 내보내고 불러온다. 저장한 배치가 없으면 대여형은 위쪽, 공용형은 아래쪽 줄에 자동으로 놓는다 — 서버에 쓰지 않으면서(FR-12A) 시연 PC를 바꿔도 되살린다.
- 무대의 글자(기기 이름표, 신호 세기, 사람 이름표, 콜아웃)는 투영한 무대 좌표에 똑바로 쓰고, 겹침도 무대 좌표의 상자로 잰다. 기기 이름표는 아래, 오른쪽, 왼쪽, 위, 한쪽 끝을 본체에 맞춘 아래, 반 줄 더 내린 아래 순서로, 신호 세기는 본체 위, 위쪽 옆, 가운데 옆, 아래, 아래쪽 옆과 한두 줄 더 위로(사람을 세운 뒤 사람 점과 이름표도 피해), 사람 이름표는 오른쪽, 왼쪽, 위, 발 아래 순서로 다른 글자를 피하는 첫 자리에 둔다. 사람은 기기 앞에서 격자 한 칸씩 비켜 서며 이름표 둘 곳이 있는 자리를 고른다. 글자는 다른 글자를 덮지 않고, 기기 본체는 바탕 테가 있어 덮을 수 있다 — 배치를 사람이 바꾸므로 고정 좌표로는 겹침을 막을 수 없다.
- 관람자의 시선을 이끈다 (2026-10-16 사용자 결정). 흐름 선이 켜지면 메시지 점이 출발지에서 도착지까지 0.6초 동안 이동한다. 그동안 메시지를 받는 쪽(서버, 기기, 소유자 폰)의 바뀐 표시와 콜아웃, 레일의 지금 단계, 폰 화면은 흐리게 있다가, 점이 도착하면 나타나며 한 번 빛난다. 보내는 쪽(AI 호스트)과 지난 단계는 강조하지 않는다 — 한 번에 볼 곳을 줄인다. 처음 그린 화면과 움직임 줄이기 설정에서는 하지 않는다 — 이미 바뀐 상태를 뒤늦게 찾는 대신, 움직임을 따라 원인에서 결과로 눈이 간다.
- 대기 장면의 비콘 안내 콜아웃은 글자를 가리지 않는 자리가 있을 때만 보인다 — 안내용이라 가리면서까지 보일 필요가 없다.
- 모니터 무대는 휠(트랙패드 핀치 포함)로 커서 자리를 중심으로 1~4배 확대·축소하고, 확대한 무대는 끌어서 옮긴다. 무대 왼쪽 아래에 확대, 축소, 전체 보기 버튼을 두고, 배율과 자리는 이 PC에 저장한다. 사람이 무대를 확대하거나 옮겼으면 패널이 열려도 방을 밀지 않는다. 설정의 배치 화면은 확대하지 않는다 (2026-10-23 사용자 결정) — 큰 화면에서 한 곳을 자세히 보거나 멀리서도 읽게 한다.
- 화면은 바탕 위에 폰 화면, 무대, 흐름 레일, 패널을 둥근 카드로 올려놓고, 카드 사이를 4px 간격으로 띄운다. 바탕은 패널과 같은 색이고, 상단 바는 바탕에 바로 둔다. 사이드 메뉴도 카드다. 메뉴에서 연 패널은 메뉴 카드 왼쪽에 이어 붙여 한 카드가 되고, 메뉴와는 경계선 하나로만 나뉜다 (VS Code 탐색기와 활동 막대처럼). 패널은 메뉴와 같은 높이로 화면 아래까지 내려온다. 패널을 열면 흐름 레일도 패널 앞까지 좁아진다. 레일이 좁아 단계 글자가 잘리면 단계마다 제목 대신 아이콘(말하기, AI 요청, 서버 확인, 기기 실행, 결과)과 상태 표시만 보이고, 숨긴 글자는 툴팁과 화면 읽기로 남긴다. 아이콘으로 바꿔도 단계가 레일 높이를 넘으면(넓은 패널을 연 낮은 화면) 번호와 상태 표시도 숨기고 아이콘만 둔다 (2026-10-23 사용자 결정) — 잘린 글자보다 아이콘이 더 잘 읽힌다. 무대는 크기를 바꾸지 않고 패널 아래에 깔리며, 가려진 무대 카드의 보이는 오른쪽 끝은 둥글게 마감한다. 설정 화면도 탭과 내용을 카드로 둔다 (2026-10-23 사용자 결정) — VS Code처럼 경계를 선 대신 간격으로 보인다.
- 폰 화면 폭, 패널 폭(보통·넓은 패널 따로), 흐름 레일 높이는 카드 사이 간격을 끌어 바꾼다. 간격 가운데에 잡을 수 있다는 점 세 개를 두고, 경계를 끌거나 화살표 키로 바꾸고, 두 번 누르거나 Home 키로 기본 크기로 돌린다. 크기는 이 PC에 저장한다. 방 밀기와 콜아웃은 실제 패널 경계를 무대 좌표로 바꿔 따르고, 콜아웃 둘 자리가 없으면 숨긴다 (2026-10-23 사용자 결정) — 시연 장소의 화면 크기와 보여 줄 곳에 맞춘다.
- 라이트·다크 전환은 화면 전체를 0.4초 동안 겹쳐 바꾸고, 움직임 줄이기 설정이면 바로 바꾼다. 테마 버튼은 글자 없이 아이콘만 두고, 누르면 바뀔 테마(다크에서는 해, 라이트에서는 달)를 채운 모양으로 그린다 (2026-10-23 사용자 결정) — 갑자기 번쩍여 눈이 아프지 않고, 글자 길이 차이로 상단 바가 흔들리지 않는다.
- 상단 바의 메뉴 대신 화면 오른쪽 끝에 세로 사이드 메뉴를 둔다 (2026-10-23 사용자 결정). 항목은 아이콘과 짧은 글자(점유, 승인, 감사, 이력, 신뢰도)이고 폭은 64px이며, 맨 아래에 톱니바퀴 아이콘의 설정을 둔다. 목록 패널은 사이드 메뉴 바로 왼쪽에 열리고, 같은 항목을 다시 누르면 닫히며 다른 항목을 누르면 바로 바뀐다. 설정을 누르면 모니터 대신 설정 화면이 열리고 위쪽 탭(배치, 폰 연결, 점검)으로 고른다. 마지막에 본 탭을 다시 연다. 설정 화면에는 사이드 메뉴가 없고, 탭 줄 오른쪽의 설정 닫기(×)나 Esc로 모니터에 돌아간다. 1500px 이하 화면에서는 사이드 메뉴만큼 좁아진 무대의 보조 글자를 키우고 설정 탭 설명을 숨긴다 — 메뉴를 펼쳐 고르고 닫는 단계를 줄이고, 지금 열린 곳을 늘 보인다.
- 패널이 열려 있으면 방만 왼쪽으로 밀어 요청과 관계있는 기기를 패널 왼쪽에 보인다 (2026-10-22 사용자 결정). 넓은 패널(감사, 이력, 신뢰도)은 대상 기기를 보일 자리가 없어 밀지 않는다. 호스트·서버·소유자 칸은 그대로 두고, 방의 왼쪽은 그 칸 뒤로 잘린다. 관계있는 기기가 칸 뒤로 들어가지 않을 만큼만 밀고, 칸 경계에 걸친 기기와 사람은 그리지 않는다. 밀었을 때 바닥(바닥판, 격자, 벽, 바닥 배선)은 잘린 쪽으로 갈수록 흐리게 지워, 문구 없이도 방이 칸 뒤로 이어지며 잘렸음을 보인다(2026-10-23 사용자 결정). 기기와 글자는 흐리지 않는다. 서버에서 방으로 가는 선은 서버 확인 글자 아래로 지나 잘린 경계에서 방 안 배선과 잇는다 — 패널이 대상 기기를 가리면 판정 흐름을 따라갈 수 없다.
- 패널이 열려 있으면 콜아웃은 (민 방 기준) 패널 왼쪽에만 둔다. 넓은 패널(감사, 이력, 신뢰도)이 열렸거나, 글자와 겹치지 않고 지시선이 기기 글자를 지나지 않는 자리가 없으면 콜아웃을 숨긴다 — 패널이 같은 내용을 보이고, 가린 콜아웃은 읽을 수 없다.
- 패널의 조회는 모니터 상태의 요청, 판정, 실행 결과, 승인, 기기 상태, 비콘 수신, 연결, 분 단위 수신 시각이 바뀌면 다시 부른다. 다시 부르는 동안 지금 결과를 둔다. 신호 세기만 바뀌면 다시 부르지 않는다 — 판정 흐름과 패널이 어긋나지 않게 하면서 조회를 줄인다.
- 무대의 사람 자리는 표시용으로 고른다. 요청한 사람은 판정이 고른 기기 앞, ASK면 확률이 높은 두 기기 사이, 그 밖에는 신호가 가장 센 기기 앞에 둔다. 다른 기기의 신호가 지금 기기보다 4dB 이상 센 상태가 2초 이어질 때만 옮기고(지금 기기의 신호가 한 묶음에서 빠지면 4dB 비교 없이 가장 센 기기가 2초 이어질 때 옮긴다), 옮길 때는 0.6초 동안 미끄러진다 (2026-10-16 사용자 결정) — RSSI가 흔들려도 점이 두 기기 앞을 오가지 않고, 순간 이동 대신 눈이 따라간다. 두 값은 표시용이라 서버 설정이 아니다. 실제 위치를 추적하지 않는다. 판정에는 쓰지 않는다 — 서버는 사람 좌표 대신 후보 확률과 RSSI를 준다 (FR-12B).
- 목 어댑터는 시각이 붙은 이벤트 이야기(`data/mock/story.ts`) 하나를 가진다. 고정 장면(`?scene=`)은 그 장면 시각까지의 이벤트를 연결 직후 한꺼번에 보낸 결과다. 조회 결과는 마지막으로 보낸 이벤트 시각까지 생긴 기록만 준다. 이력과 신뢰도 집계는 AI에 응답한 뒤, 감사 로그 줄은 그 줄의 이벤트가 온 뒤에 보인다. 신뢰도의 실시간 판정 수는 시연 세션 시작부터 그 시각까지의 이력 수와 같고, 승인·대여 조회에 나온 사용은 이력에도 있고, 점검의 비콘 수신은 모니터 상태를 따른다 — 장면과 패널이 같은 시각을 보이게 한다.
- 목 어댑터는 `?scene=`으로 장면을 고정한다. 값이 없으면 대기 장면이다. `?scene=play`는 장면을 차례로 한 번 재생한다. 처음으로 돌아가면 고장 격리가 복구 없이 풀린 것처럼 보이기 때문이다.
- 목 어댑터의 `?scene=live`는 이벤트 이야기를 시각 순서대로 보낸다. 판정 이벤트는 실제처럼 0.2초 안에 보내고, 명령 뒤 결과를 기다리는 간격은 2초 이상으로 늘리고, 이벤트 사이의 조용한 구간은 빨리 감는다. 비콘 신호 세기는 0.5초마다 보낸다. 이야기가 끝나면 실제 속도로 계속 간다 — 서버 없이도 이벤트가 도착하는 순서대로 화면이 바뀌는 흐름을 보인다. 상단 바에 목 데이터라고 적는다.
- 목 어댑터는 사람마다 가짜 폰 화면을 목 전용 이벤트(`mock_phone`)로 준다. 미러링 창이 없을 때 이 화면을 보인다. 서버 어댑터는 이 필드를 비우고 미러링 영상만 쓴다.
- 폰 화면은 상단 바 아래부터 화면 아래까지 쓰고, 흐름 레일은 무대 아래에만 둔다. 실제 미러링 영상은 가짜 폰 틀(카메라 장식, 안쪽 테두리) 없이 영상 비율 그대로 칸 높이를 채운다 (2026-10-23 사용자 결정) — 실제 폰 영상에는 상태 표시줄과 모서리가 이미 들어 있어 가짜 틀과 겹치고, 틀 비율이 영상과 다르면 위아래에 빈 띠가 생긴다. 폰은 USB로 연결해 QuickTime 새로운 동영상 녹화 창에 띄우고, 폰은 손으로 조작한다.
- 폰 칸 머리글은 한 줄(왼쪽 사람 이름, 오른쪽 자동 전환 상태)로 두고, "폰 화면" 표시는 아래 줄로 옮긴다. 폰 화면 폭은 폰이 칸 높이를 다 쓰는 폭(칸 높이 × 화면 비율, 실제 영상이 세로면 영상 비율, 그 밖에는 9:19.5)보다 좁게 줄일 수 없다. 창이 커져 이 하한이 저장한 폭보다 커지면 하한을 쓰되, 하한은 최대 폭(화면 폭의 40%)을 넘지 않는다. 폰을 뽑아 QuickTime 창이 검은 가로 화면이 되어도 폰 칸이 무대를 밀어내지 않는다 (2026-10-23 사용자 결정) — 글이 위로 쌓이면 폰 화면 높이가 줄고, 칸이 폰보다 좁으면 폰 비율이 무너진다.
- 미러링 창 고르기의 권한 흐름 (2026-10-23 사용자 결정) — 페이지는 운영체제 권한을 미리 알 수 없고, 공유 창은 사람이 누른 순간에만 열 수 있다. 공유 창이 열린 채 macOS 권한 창이 뜨면 공유 창을 닫을 때까지 권한 창이 시스템 설정까지 덮는 것을 확인했다.
  - macOS에서 이 PC가 공유에 성공한 적이 없으면 공유 창 대신 대시보드의 권한 안내를 먼저 띄운다. Windows와 그 밖은 바로 공유 창을 연다.
  - 안내의 "설정 열기"는 운영체제의 화면 공유 권한 화면을 바로 연다 (macOS `x-apple.systempreferences:…Privacy_ScreenCapture`, Windows `ms-settings:privacy`). 연 뒤에는 "창 고르기"를 앞세운다.
  - 설정을 연 사람은 이 PC 브라우저에 남긴다. 권한을 켠 뒤 브라우저를 다시 열면 폰 연결 탭에서 안내를 이어서 띄운다.
  - 공유에 성공하면 이 PC에 남겨 다음부터는 안내 없이 공유 창을 연다.
  - 실패는 브라우저 오류로 나눈다. `NotAllowedError`에 "system"이 있으면 운영체제가 막은 것이라 운영체제에 맞는 권한 안내를 다시 띄우고, 없으면 사람이 취소한 것이라 아무것도 보이지 않는다. 화면을 잡지 못했거나 쓸 수 없는 브라우저면 그 사람 카드에 안내한다.
  - 안내가 열려 있으면 Esc는 안내만 닫는다.
- 테스트는 Vitest(계산·컴포넌트)와 Playwright(장면별 해상도·넘침·대비)로 한다.
- 서버 어댑터 (2026-10-24 담당자 결정: 대시보드에 필요한 서버 작업과 어댑터를 이번에 함께 만든다).
  - `?source=server`일 때만 쓴다. 값이 없으면 지금처럼 목 어댑터다 — 기존 장면 주소와 화면 시험을 그대로 둔다.
  - 서버 주소는 대시보드를 연 주소와 같은 출처다. Vite 개발·미리보기 서버가 `/dashboard`(WebSocket 포함)를 NearPilot 서버(`NEARPILOT_SERVER`, 기본 `http://127.0.0.1:8000`)로 넘긴다 — 서버에 CORS를 열지 않는다.
  - 소유자 토큰은 입력 화면에서 받아 이 탭의 세션 저장소에만 둔다. 주소에 넣지 않는다 — 주소는 방문 기록과 화면 공유에 남는다.
  - 스트림 메시지 하나(`{"v": 1, "events": [...]}`)를 한 묶음으로 넘긴다. 연결 상태는 `link`로 넘기고, 끊기면 1초부터 두 배씩 최대 10초까지 늘려 다시 연결한다. 표시용 값이라 서버 설정이 아니다.
  - 시각은 서버가 ISO 8601(시간대 포함)로 준다. 어댑터가 이 PC의 지역 시각 문자열로 바꾼다. 형식은 목 데이터의 같은 필드와 같다 (이벤트 `HH:MM:SS.mmm`, 목록의 시각은 그 필드의 목 형식) — 화면은 목 데이터로 검증한 문자열을 그대로 쓴다.
  - 서버 값 가운데 화면 모델에 없는 것은 어댑터가 옮긴다: 실행 상태 `pending`·`in_progress`는 `sent`, `not_sent`는 실행 없음. `rejected`(기기가 실행 전에 거절, 격리 없음)는 스트림 `exec_result`와 조회 REST 둘 다 모델에 `rejected`로 더한다 — 화면은 고장 격리가 아니라 "기기가 거절"로 그린다. 승인 이벤트의 `approved`·`denied`는 모델에 더해 소유자 알림을 끝내고, 끝난 까닭(승인·거절·만료)을 요청에 남긴다 — 화면은 까닭마다 다른 문구를 쓴다 (승인: 다시 요청하면 실행, 거절: 실행 안 함, 만료: 소유자 응답 없음). 요청 상세 조회(REST)는 까닭(`accessEnd`)을 주지만 승인·거절의 끝난 시각은 없다 (서버가 저장하지 않는다). 요청 패널은 그 시각을 `—`로 보인다.
  - 점유 패널은 대여형 점유 세션과 공용 조명을 지금 쓰는 사람을 함께 보인다 (서버 `uses`가 둘 다 준다). 안내 문구도 그렇게 쓴다.
  - 신뢰도의 `evaluation`과 `confusion`은 없을 수 있다 (architecture.md §5).
- 무대는 장소 둘을 주 장소(크게)와 작은 방으로 그린다 (2026-10-24 사용자 결정). 두 방을 같은 크기로 나란히 그리면 방 하나에 맞춘 글자 배치 규칙과 배치 파일을 다시 짜야 하고 글자가 작아진다. 작은 방은 무대 오른쪽 아래 빈자리에 장소 이름, 기기 상태 색, 사람 글자만 그린다. 기기 이름과 상태 글자는 그 장소로 고정해서 본다. 작은 방은 무대의 일부라 무대를 확대하면 함께 커진다 — 지금 판정이 흐르는 장소는 크게 읽히고, 다른 장소의 사람도 놓치지 않는다.
- 사람의 장소는 무대에 세우는 기기(`near`)의 장소다 — `near`는 이미 4dB·2초 규칙으로 흔들림을 거르므로 문턱에서 장소가 오가지 않는다. 비콘이 끊겨도 사람의 마지막 장소를 기억해, 같은 장소로 돌아온 사람은 옮긴 사람이 아니다 — 끊김이 전환을 일으키지 않게 한다. 주 장소는 진행 중인 요청의 장소, 요청이 없으면 마지막으로 장소를 옮긴 사람의 장소, 둘 다 없으면 그대로다 (2026-10-24 사용자 결정: 전환이 눈에 거슬리지 않으면 방식은 위임). 한 묶음에서 여럿이 옮기면 사람 목록 순서의 마지막 사람을 쓴다. 이 계산은 고정 중에도 이어 하고, 고정을 풀면 그 결과로 돌아간다. 화면을 새로 열면 처음 본 사람은 옮긴 사람이 아니고, 요청이 없으면 사람이 있는 첫 장소를 둔다 — 처음 본 사람을 모두 옮긴 사람으로 보면 사람 목록 순서가 장소를 정한다. 그래서 주 장소는 모니터 상태와 함께 이 화면이 앞서 계산한 장소에도 기대고, 같은 상태라도 계속 본 화면과 새로 연 화면의 주 장소가 다를 수 있다. 주 장소가 바뀌면 방과 작은 방을 0.4초 동안 겹쳐 바꾸고, 움직임 줄이기 설정이면 바로 바꾼다.
- 장소 고정은 이 화면을 연 동안만 둔다. 이 PC에 저장하지 않는다 — 지난 시연에서 고정한 채 둔 장소가 다음 시연의 흐름을 가리지 않게 한다.
- 배치는 장소마다(`placeId`) 따로 저장하고, 설정의 배치 화면은 장소 탭으로 고른다. 탭은 배치 화면을 처음 연 순간 무대의 장소를 열고, 그 뒤로는 무대의 장소가 바뀌어도 그대로 두며, 마지막에 본 탭은 화면을 연 동안만 기억한다. 장소 이름 열쇠로 저장한 이전 배치는 `placeId` 배치가 없을 때 읽고 기본 배치로 되돌리면 함께 지우며, 파일의 `place`가 장소 이름이어도 같은 장소로 본다 — 이전 버전으로 맞춘 시연 PC의 배치를 잃지 않는다.

## 7. 가정

- FR-12B 이벤트는 `src/model/events.ts`의 종류로 온다: 도구 호출 도착(`mcp_call`)과 응답(`mcp_result`), 판정 단계(`step`), 후보 확률(`posterior`), 판정(`verdict`), 기기 상태 전이(`transition`, FAULT 원인 포함), MQTT 명령(`command`)과 실행 결과(`exec_result`), 승인 신청과 결정(`approval`), 비콘 수신(`beacon`, 이름 포함)과 RSSI(`rssi`), 감사 로그(`audit`). 모든 이벤트에 서버 시각이 붙는다. 서버 메시지(architecture.md §5 "WebSocket")를 이 종류로 옮기는 일은 서버 어댑터가 맡는다
- 연결하면 서버가 진행 중인 요청과 지금 상태를 이벤트로 다시 보낸다 (architecture.md §5 "WebSocket")
- 사람 이름(`방문자 A`, `방문자 B`)과 글자는 서버가 붙여 비콘 이벤트와 조회 REST에 같게 준다 (architecture.md §5). 이름은 서버 프로세스가 끝날 때까지 유지한다 (architecture.md §5 "WebSocket")
- 조회 REST의 장소 정보는 등록된 장소 목록(장소마다 `placeId`, 이름, 근접 모델·보정 버전, 기기 목록)과 배치 화면의 약한 신호 기준(dBm) 하나다. 좌표는 없다. `placeId`와 `nodeId`는 목록 전체에서 한 번씩만 나온다 (architecture.md §5 "대시보드 조회"의 `places`). 시연의 두 장소는 한 소유자가 갖는다 (2026-10-23 담당자 확정).
- 대시보드 PC와 서버의 시간대가 같다. 이력의 시각 구간(`HH:MM~HH:MM`)은 서버 시간대의 오늘로 읽히고(architecture.md §5) 화면은 이 PC의 시각으로 보이기 때문이다. 시연은 한 PC에서 하므로 같다
