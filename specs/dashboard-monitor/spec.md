# 운영 대시보드 모니터 (목 데이터)

- 담당: dnnals (대시보드)
- 요구사항: FR-12A, FR-12B, NFR-12
- 따르는 결정: #168

## 1. 왜

- `dashboard/`가 비어 있다. 시연 관객과 운영자가 판정 흐름(누가 무엇을 요청했고, 서버가 무엇을 확인했고, 결과가 어떤지)을 볼 화면이 없다.
- 대시보드 조회 REST와 모니터링 WebSocket은 경로와 메시지 형식이 미결이다 (FR-12A, FR-12B). 서버 계약을 기다리면 화면 작업을 시작할 수 없다.

## 2. 무엇

- 입력: 데이터 소스(`DataSource`)가 주는 장소 상태 스냅숏과 조회 결과. 이번 작업의 데이터 소스는 목 어댑터 하나다.
- 출력: 브라우저에서 여는 정적 웹 앱. 화면은 승인한 화면 설계 목업(15화면, 다크·라이트)과 같은 구조다.
  - 모니터: 상단 바, 폰 미러링(왼쪽), 무대(평면도), 흐름 레일
  - 패널(무대 위에 겹쳐 열림): 요청 상세, 기기 상세, 점유·대여 현황, 승인 현황, 감사 로그, 요청·판정 이력, 신뢰도 지표
  - 설정: 배치·신호 점검, 폰 연결, 점검
  - 연결 끊김 안내
- 바뀌는 상태: 서버 상태는 바꾸지 않는다. 이 PC의 표시 설정(테마, 미러링 창 연결, 자동 전환)만 브라우저에 둔다.
- 약속:
  - 화면 코드는 `DataSource` 인터페이스에만 의존한다. 서버 계약이 정해지면 서버 어댑터만 더한다.
  - 레일 문구, 무대의 흐름 선, 콜아웃, 흐리게 하기는 스냅숏에서 규칙으로 계산한다. 장면별 고정 값을 두지 않는다.

## 3. 제약

- 대시보드는 서버에 쓰지 않는다. 쓰기 요청을 보내는 버튼과 코드가 없다 (FR-12A).
- 빌드 결과는 외부 네트워크 없이 동작한다. 글꼴과 모든 자산을 번들에 넣는다 (NFR-12).
- 사람은 가명(방문자 A, 소유자)으로만 보인다. 사용자 ID를 화면에 쓰지 않는다 (FR-11, NFR-08).
- 판정 값, 사유 코드, 단계, 상태 이름은 `server/src/nearpilot/shared/enums.py`에 있는 값만 쓴다.
- 설정값(임계값, 대여 시간)은 숫자를 지어내지 않고 데이터 소스에서 받거나 "설정값"으로 표시한다.
- 미결 항목(알림 수단, 평가 기준 등)은 "미결"로 표시한다.

## 4. 경계

### 고치는 곳
- `dashboard/`

### 고치지 않는 곳
- 항상: `docs/`, `AGENTS.md` (Gotchas 절은 제외), `server/src/nearpilot/shared/`, `server/pyproject.toml`, `.github/`
- 이 작업: `server/` 전부

### 다른 영역과 닿는 곳
| 계약 | 사용 또는 제공 | 상대 영역 |
|---|---|---|
| 대시보드 조회 REST (경로·형식 미결) | 사용 예정. 이번에는 목 어댑터로 대신한다 | API |
| 모니터링 WebSocket (형식 미결) | 사용 예정. 이번에는 목 어댑터로 대신한다 | API |

### 만들지 않는 것
- 서버 어댑터. 조회 REST와 WebSocket 형식이 정해진 뒤 따로 만든다.
- 서버의 `api/rest/`, `api/ws/`
- CI 작업. `.github/`는 고치지 않는다. 테스트는 로컬에서 실행한다.

## 5. 예외 상황
| 상황 | 기대 동작 | 테스트 |
|---|---|---|
| 데이터 소스 연결이 끊김 | 마지막 화면을 유지하고 연결 끊김 안내와 마지막 수신 시각을 보인다 | `offline` 장면 e2e |
| 진행 중인 요청이 없음 | 대기 안내와 다섯 단계 설명을 보인다 | `idle` 장면 e2e, 레일 단위 |
| 판정이 ASK, NEED_APPROVAL, BUSY, DENY | 기기를 실행하지 않았다고 레일에 보이고, 멈춘 단계를 강조한다 | 레일 단위 |
| 실행 결과 불명으로 FAULT | 대상 기기를 고장 격리로 보이고 기기 상세에 원인을 보인다. 복구 화면과 버튼은 없다 (복구는 소유자 스크립트) | `fault` 장면 e2e |
| 미러링 창이 없음 | 폰 자리에 "미러링 창 없음"을 보인다 | 폰 단위 |
| 브라우저 저장소를 쓸 수 없음 | 기본 설정(다크, 자동 전환 켬)으로 동작한다 | 설정 단위 |
| 1366×768 ~ 3840×2160 | 1920×1080 기준 비율로 확대·축소하고 넘침·겹침·가로 스크롤이 없다 | 해상도 e2e |

## 6. 결정

- React + Vite + TypeScript — 팀이 쓰는 웹 스택 중 정적 빌드가 가장 단순하다.
- 목업 CSS를 그대로 쓰고 상태는 `data-*` 속성으로 둔다 — 검증한 화면을 그대로 재현한다. 인라인 style을 쓰지 않는다.
- 글꼴은 `@fontsource` 패키지로 번들한다 — NFR-12.
- 데이터 소스는 스냅숏 구독 하나와 조회 함수들로 나눈다 — FR-12B 스트림과 FR-12A 조회 REST에 대응한다.
- 화면은 스냅숏에서 순수 함수로 계산한다 — 서버 어댑터를 붙여도 화면 로직을 다시 쓰지 않는다.
- 판정이 ASK, NEED_APPROVAL이거나 기기가 새로 FAULT가 되면 해당 상세 패널을 자동으로 연다. ×로 닫는다.
- 목 어댑터는 `?scene=`으로 장면을 고정한다. 값이 없으면 대기 장면이다. `?scene=play`는 장면을 차례로 재생한다.
- 테스트는 Vitest(계산·컴포넌트)와 Playwright(장면별 해상도·넘침·대비)로 한다.

## 7. 가정

- 서버 스냅숏은 기기 상태(FAULT 원인 포함), 사람별 위치와 비콘 신호, 진행 중인 요청의 단계별 결과를 담는다 — 미결: FR-12B 메시지 형식 (이슈 없음)
- 사람 가명은 서버가 준다 — 미결: 가명 생성 위치 (이슈 없음)
