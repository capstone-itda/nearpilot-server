# 기기 보고의 연결 검증과 CORE 재인계

- 담당: 이 작업을 지시한 담당자 (상태 관리의 IOT 구현 범위)
- 구현 브랜치: `feat/iot-event-delivery`
- 요구사항: FR-04, FR-05, FR-07, FR-13, FR-20, NFR-08
- 따르는 결정: architecture.md에 반영한 #19, #31, #32, #38, #140~#143이다.
- 상태: 구현 전 초안이다. 선행 작업은 `iot-messages`와 연결 모듈이다.

## 1. 왜

형식이 맞아도 오래된 보고와 이전 연결의 관측은 현재 판정에 쓸 수 없다.
CORE 인계 실패를 전달 완료로 버리면 실행 결과와 장애 근거가 사라진다.

## 2. 무엇

- 입력: 형식을 검증한 기기 보고, MQTT 전달 정보, 최초 수신 시각과 적용 설정이다.
- 출력: `NodeEventSink`의 다섯 호출과 명령 대기 모듈에 넘기는 검증한 결과다.
- 바뀌는 상태: 현재 연결, 토픽별 관측 순번, 최신성 기준과 미인계 보고의 메모리다.
- 약속:
  - 관측과 실행 결과를 다른 최신성 규칙으로 검증한다.
  - 인계 실패를 기록하고 같은 보고를 다시 인계한다.
  - 명령 대기를 깨우는 동작은 CORE 잠금 대기와 분리한다.
  - 첫 구현의 재인계는 실행 중 메모리에 한한다. 재시작 복원은 보장하지 않는다.

## 3. 제약

- 발표는 발견에만 쓴다. retained 발표만으로 현재 연결·온라인·안전을 확정하지 않는다 (FR-04, FR-13).
- 신선한 실시간 `status`로 현재 연결을 확인한다. 현재 연결 확인 전 RSSI를 판정에 쓰지 않는다 (FR-05, FR-13).
- 이전 연결·역순·중복 관측을 현재 판정에 쓰지 않는다. 새 연결도 오래된 관측으로 되돌리지 않는다 (FR-13).
- 시각 오차를 포함한 관측 나이와 허용 오차 밖의 미래 시각을 검사한다 (FR-07, #140).
- RSSI 허용 나이는 `beacon_recent_sec`, 검사 허용 나이는 `safety_report_max_age_sec`다 (FR-05, FR-07).
- 상태 보고의 허용 나이와 연결 동률 규칙은 S1을 먼저 확정한다 (architecture.md §5 MQTT 6절).
- 실제 기기의 검증되지 않은 시각 오차를 0으로 두지 않는다. 같은 PC 시뮬레이터의 가정과 구분한다 (FR-07, #140).
- 결과의 오래된 시각·이전 연결을 관측의 거부 기준으로 버리지 않는다. 원래 명령의 정산은 CORE가 연결을 확인한다 (FR-07).
- 과거 실행 결과는 현재 온라인·안전·연결을 갱신하지 않는다 (FR-07, FR-13).
- 결과 사건의 ID·내용을 보존한다. 같은 ID의 상충 보고를 정상 중복으로 숨기지 않는다 (FR-07).
- 검사 결과는 요청의 기기·ID·대상 연결·기준·시각을 대조한다. 종료와 확인 불능 타이머는 CORE가 맡는다 (FR-20).
- v1 근거는 §4 표를 따른다. 만들 수 없는 bool 값을 꾸미지 않는다 (FR-20, #141, #143).
- 재인계는 최초 `received_at`과 원래 모델을 유지한다. 늦은 재인계를 신선한 관측으로 만들지 않는다 (FR-05, FR-13).
- CORE 인계가 성공하기 전에 중복 검사를 전달 완료로 표시하지 않는다 (FR-07, architecture.md §4 기기 보고의 인계).
- 등록 비콘의 선택과 저장은 CORE·DB가 맡는다. IOT는 수집 여부·라벨을 받지 않는다 (FR-05).
- 진단에는 기기·토픽·검증 실패 원인을 기록한다. 자격정보 원문과 임의의 본문 전체를 기록하지 않는다 (NFR-08).
- 재인계 용량·주기·포화 동작은 S4를 먼저 확정한다 (requirements.md §1.2).

## 4. 경계

### 고치는 곳

- `server/src/nearpilot/iot/mqtt/`의 보고 검증·현재 연결·재인계 파일이다.
- `server/tests/iot/`의 보고 검증·인계 테스트다.

### 고치지 않는 곳

- 항상: `docs/`, `AGENTS.md`의 Gotchas 밖, `server/src/nearpilot/shared/`, `server/pyproject.toml`, `.github/`다.
- 이 작업: 본문 스키마·연결 수명주기·명령 대기, CORE·DB·API와 펌웨어다.

### 다른 영역과 닿는 곳

| 계약 | 사용 또는 제공 | 상대 영역 |
|---|---|---|
| `NodeEventSink.on_announce` | 호출한다 | CORE |
| `NodeEventSink.on_rssi`, `on_status` | 호출한다 | CORE |
| `NodeEventSink.on_result`, `on_safety_check_result` | 호출한다 | CORE |
| 기기 보고의 shared 모델 | 사용한다 | shared |

### 만들지 않는 것

- DB 조회·저장, 온라인 시각의 영속화와 CORE의 기기별 잠금이다.
- 실행·반납의 정산, 반납 재검사와 `FAULT` 복구다.
- 재시작 뒤 미인계 보고를 복원하는 저장소다.
- 새 안전 기준과 실제 센서 검증이다.

| 새 연결의 관측이 더 오래됐다 | 현재 연결을 되돌리지 않는다 | `test_FR13_session_cannot_move_backwards` |

| 미인계 보고가 있는 서버가 재시작한다 | 복원을 보장하지 않는다. 성공·미전송을 추정하지 않는다 | `test_FR07_restart_does_not_claim_delivery` |

## 6. 결정

- 보고 검증·CORE 재인계를 명령 대기와 분리한다 — 담당자가 2026-10-15에 선택했다.
- Paho 수신과 CORE 인계를 다른 작업으로 둔다 — 동기 실행의 잠금 대기와 교착을 막는다.
- 첫 구현은 실행 중 메모리 재인계만 보장한다 — 담당자가 2026-10-15에 선택했다.
- 재인계 중 최초 수신 시각을 보존한다 — 저장 지연으로 관측의 최신성을 바꾸지 않는다.

## 7. 가정

- 상태 허용 나이·연결 전환 동률은 S1, 재인계 용량·주기·포화는 S4가 미결이다.
- 실제 기기의 시각 신뢰 검증과 허용 오차는 #140의 후속 실측을 기다린다.
- 시뮬레이터는 같은 PC의 시계를 쓴다. 이 가정을 실제 기기 설정으로 복사하지 않는다.
- 서버 재시작 때 미인계 보고를 잃을 수 있다. QoS 1을 CORE 저장 완료의 보장으로 설명하지 않는다.
- CORE의 기존 근거 검증 차이는 계약 검토 문서에 기록한다. IOT는 문서의 필수 근거를 따른다.
