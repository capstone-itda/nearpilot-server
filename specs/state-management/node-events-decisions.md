# 기기 이벤트의 실행 문맥 조회 계약 초안

이 문서는 담당자에게 넘기는 초안이다. 팀 결정이 아니며 이슈를 생성하지 않았다.

## 질문

명령 ID로 원래 실행 문맥을 조회하는 접점을 어느 영역이 제공하는가?
재시작 뒤에도 원래 요청과 적용한 설정을 어떻게 보존하는가?

## 맥락

- 관련 영역: 판정·상태 관리·DB다.
- 관련 요구사항: FR-07, FR-18, FR-19다.
- IOT는 `NodeResult.command_id`를 전달한다. 실행 서비스는 원래 `ExecutionContext`를 받는다.
- `ExecutionStore.execution()`은 내부 요청 ID로 명령을 조회한다. 명령 ID로 요청을 찾는 접점은 없다.
- 복원 묶음의 요청에는 `UseRequest`가 있다. 적용한 `Settings`는 없다.
- `restore_pending()`은 완료한 모든 명령의 원래 요청을 반환하는 접점이 아니다.
- 현재 설정으로 문맥을 다시 만들면 최초 대여의 시간 기준과 재검사 입력을 바꿀 수 있다.
- 기기 이벤트 서비스는 `context_for(command_id)`를 필수 함수로 받는다.
- 문맥 부재와 조회 실패는 예외로 알린다. 새 명령을 만들거나 `execute()`를 다시 호출하지 않는다.

## 선택지

### A. 원래 실행 문맥의 저장과 조회

- 판정과 DB가 원래 요청·확정 대상·점유·사용분·실행 종류·적용 설정을 보존한다.
- 명령 ID로 원래 문맥을 반환하는 공동 조회 접점을 제공한다.
- 서버 조립이 기기 이벤트 서비스의 조회 함수에 접점을 연결한다.

### B. 결과 저장 전용 문맥 계약

- 원래 실행 문맥 대신 결과 정산에 필요한 영속 필드를 따로 정한다.
- 실행 서비스와 DB가 새 결과 저장 계약을 따른다.

## 제안

A를 제안한다. 기존 실행 서비스의 입력을 보존할 수 있다.
설정의 보존 주체·형식과 명령 ID 조회는 관련 담당이 먼저 합의한다.
서버 조립은 모든 상태 관리 서비스에 같은 복구 서비스와 기기 잠금을 주입한다.
이 계약과 서버 시작 조립 전에는 재시작 뒤 결과 수신 전체를 완료로 표시하지 않는다.
