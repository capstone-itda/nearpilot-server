# 재시작 복원의 선행 계약 이슈 초안

이 문서는 담당자에게 넘기는 초안이다. 팀 결정이 아니며 이슈를 생성하지 않았다.

## 초안 1: 예약 만료 취소 사유

### 질문
예약 대기 제한을 넘긴 확실한 미전송의 취소에 어떤 사유 코드를 쓰는가?

### 맥락
- 관련 영역: CORE 상태 관리, 판정, DB다.
- 관련 요구사항: FR-19, FR-20이다.
- 입력: 저장한 예약 시각과 미전송 상태다.
- 출력: 사유를 보존한 예약 취소다.
- 바뀌는 상태: 요청의 명령, 점유 세션과 승인 사용분이다.
- 약속: 전송 여부가 불명이면 예약과 사용분을 반환하지 않는다.
- 지금 정해야 하는 이유: `cancel_not_sent()`는 `ReasonCode`를 요구한다. 현재 값에는 예약 만료 사유가 없다.

### 선택지
- A. 예약 만료 전용 사유 코드를 공동 계약에 추가한다.
- B. 취소 원인을 전달하는 공동 모델을 따로 정한다.

### 제안
A를 제안한다. 검사 오류용 `RECHECK_FAILED`와 `INTERNAL_ERROR`를 정상 만료에 재사용하지 않는다.

## 초안 2: 명령 미연결 예약의 취소

### 질문
명령을 연결하지 않은 예약을 `cancel_not_sent(expected=PENDING)`로 취소할 수 있는가?

### 맥락
- 관련 영역: CORE 상태 관리, DB다.
- 관련 요구사항: FR-19, FR-20이다.
- 입력: `PendingRequestRecord`와 명령이 없는 대여형 또는 공용형 예약이다.
- 출력: 원자적인 예약과 승인 사용분의 취소다.
- 바뀌는 상태: 요청과 연결한 예약 및 승인 사용분이다.
- 약속: 취소를 위해 가짜 물리 명령을 만들지 않는다.
- 지금 정해야 하는 이유: 현재 계약은 명령 부재 때의 기대 상태를 명시하지 않는다.

### 선택지
- A. 기존 취소 접점이 명령 미연결 요청도 받는다고 명시한다.
- B. 명령 미연결 요청의 취소 접점을 공동 계약에 추가한다.

### 제안
DB 담당과 A의 가능 여부를 확인한다. 계약 확인 전에는 요청과 사용분을 보존하고 실행을 차단한다.

## 초안 3: 판정과 실행의 복원 상태 조회

### 질문
판정과 실행이 기기별 복원 완료를 어떤 공동 접점으로 확인하는가?

### 맥락
- 관련 영역: CORE 상태 관리, 판정, 서버 조립이다.
- 관련 요구사항: FR-19다.
- 입력: 기기 ID와 현재 복원 상태다.
- 출력: 현재 기기의 실행 가능 여부다.
- 바뀌는 상태: 없음이다.
- 약속: 최초 조회 실패와 현재 연결 미확인 상태에서는 새 실행을 허가하지 않는다.
- 지금 정해야 하는 이유: `shared`에는 복원 상태를 조회하는 접점이 없다.

### 선택지
- A. 상태 관리가 기기별 실행 가능 여부를 제공하는 공동 접점을 추가한다.
- B. 서버 조립에서 내부 접점을 주입하는 방법과 책임을 합의한다.

### 제안
판정 담당과 후보 제외 및 전송 직전 검사의 책임을 함께 정한다. 내부 `can_execute()`의 단위 검증을 실제 연결 완료로 보지 않는다.
