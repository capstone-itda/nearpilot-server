# 실행 인계의 선행 계약 이슈 초안

이 문서는 담당자에게 넘기는 초안이다. 팀 결정이 아니며 이슈를 생성하지 않았다.

## 초안 1: 확실한 미전송의 취소 사유

### 질문
예약 만료·현재 연결 없음·IOT 미전송 증명에 어떤 사유 코드를 쓰는가?

### 맥락
- 관련 영역은 상태 관리·판정·DB다. 요구사항은 FR-06, FR-19다.
- `cancel_not_sent`는 `ReasonCode`를 받지만 세 원인에 맞는 값이 없다.
- 재검사 거부는 원래 사유로 취소할 수 있다. 정상 미전송에 검사 오류 사유를 재사용하지 않는다.

### 선택지
- A. 원인별 사유 코드를 공동 계약에 추가한다.
- B. 취소 원인을 전달하는 공동 모델을 정한다.

### 제안
A를 제안한다. 계약 전에는 예약과 사용분을 보존하고 전송을 막는다.

## 초안 2: 재검사 밖의 실행 중단 사유 전달

### 질문
구동 경합·상태 충돌·복원 미완료·연결 없음의 사유를 판정에 어떻게 전달하는가?

### 맥락
- 관련 영역은 상태 관리·판정이다. 요구사항은 FR-18, FR-19다.
- `ExecutionResult.recheck`는 재검사가 막았을 때의 판정이다.
- `ExecutionResult`에는 다른 중단 사유를 담는 필드가 없다.

### 선택지
- A. 실행 결과에 별도 사유를 추가한다.
- B. 실행 중단 결과의 공동 모델을 정한다.

### 제안
A를 제안한다. 내부 `blockers`를 호스트 응답 계약으로 공개하지 않는다.

## 초안 3: 정상 운영 중 예약 시각의 조회

### 질문
실행 인계 전 예약과 명령 미연결 예약의 시각을 어떤 접점으로 확보하는가?

### 맥락
- 관련 영역은 상태 관리·판정·DB다. 요구사항은 FR-19다.
- `ExecutionContext`에는 예약 시각이 없다. 명령의 `reserved_at`은 연결 뒤에만 읽을 수 있다.
- 정상 운영 중 전체 예약을 감시하는 조회 계약과 명령 미연결 취소의 약속이 필요하다.

### 선택지
- A. 예약 조회와 기존 취소 접점의 명령 부재 동작을 명시한다.
- B. 예약 만료를 위한 공동 접점을 추가한다.

### 제안
DB 담당과 A를 먼저 확인한다. 기존 명령의 예약 시각은 전송 직전에 검사한다.
