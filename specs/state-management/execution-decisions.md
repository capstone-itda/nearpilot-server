# 실행 인계의 선행 계약 이슈 초안

이 문서는 담당자에게 넘긴 초안이다. 팀 결정이 아니다. 초안 1은 #78, 초안 2는 #79, 초안 3은 #80으로 올렸다.

## 초안 1: 확실한 미전송의 취소 사유

### 질문
예약 만료·현재 연결 없음·IOT 미전송 증명에 어떤 사유 코드를 쓰는가?

### 맥락
- 관련 영역: 상태 관리·판정·DB다.
- 관련 요구사항: FR-06, FR-19다.
- 입력: 예약 만료·현재 연결 없음·IOT 미전송 증명이다.
- 출력: 원인을 보존한 확실한 미전송 취소다.
- 바뀌는 상태: 이번 요청의 명령·점유 예약·승인 사용분이다.
- 약속: 전송 여부가 불명이면 예약과 사용분을 반환하지 않는다.
- 지금 정해야 하는 이유: `cancel_not_sent`는 `ReasonCode`를 받지만 세 원인에 맞는 값이 없다.

### 선택지
#### A. 원인별 사유 코드
- 결과: 각 취소 원인을 공동 사유 코드로 전달한다.

#### B. 취소 원인 모델
- 결과: 별도 공동 모델로 취소 원인을 전달한다.

### 제안
A를 제안한다. 계약 전에는 예약과 사용분을 보존하고 전송을 막는다.

## 초안 2: 재검사 밖의 실행 중단 사유 전달

### 질문
구동 경합·상태 충돌·복원 미완료·연결 없음의 사유를 판정에 어떻게 전달하는가?

### 맥락
- 관련 영역: 상태 관리·판정이다.
- 관련 요구사항: FR-18, FR-19다.
- 입력: 구동 경합·상태 충돌·복원 미완료·연결 없음이다.
- 출력: 중단 사유를 구분한 실행 결과다.
- 바뀌는 상태: 없음이다.
- 약속: 재검사 결과와 다른 중단 사유를 구분한다.
- 지금 정해야 하는 이유: `ExecutionResult`에는 재검사 밖의 중단 사유를 담는 필드가 없다.

### 선택지
#### A. 실행 결과의 사유 필드
- 결과: 기존 실행 결과에 중단 사유를 담는다.

#### B. 실행 중단 결과 모델
- 결과: 별도 공동 모델로 중단 사유를 전달한다.

### 제안
A를 제안한다. 내부 `blockers`를 호스트 응답 계약으로 공개하지 않는다.

## 초안 3: 정상 운영 중 예약 시각의 조회

### 질문
실행 인계 전 예약과 명령 미연결 예약의 시각을 어떤 접점으로 확보하는가?

### 맥락
- 관련 영역: 상태 관리·판정·DB다.
- 관련 요구사항: FR-19다.
- 입력: 인계 전 예약과 명령 미연결 예약이다.
- 출력: 저장한 예약 시각과 만료 예약의 취소다.
- 바뀌는 상태: 만료한 예약과 승인 사용분이다.
- 약속: 실행 인계 시각부터 예약 대기를 다시 세지 않는다. 취소를 위해 가짜 명령을 만들지 않는다.
- 지금 정해야 하는 이유: `ExecutionContext`에는 예약 시각이 없다. 명령의 `reserved_at`은 연결 뒤에만 읽을 수 있다.

### 선택지
#### A. 기존 조회와 취소의 약속 명시
- 결과: 기존 접점으로 예약 시각을 읽고 명령 미연결 예약을 취소한다.

#### B. 예약 만료 접점 추가
- 결과: 새 공동 접점으로 만료 조회와 취소를 요청한다.

### 제안
DB 담당과 A를 먼저 확인한다. 기존 명령의 예약 시각은 전송 직전에 검사한다.
