# 복구 조회·승인의 선행 계약 이슈 초안

이 문서는 담당자에게 넘기는 초안이다. 팀 결정이 아니며 이슈를 생성하지 않았다.

## 초안 1: 장소 소유권 조회

### 질문
CORE가 복구 조회·승인마다 기기 장소의 소유권을 어떤 공동 접점으로 확인하는가?

### 맥락
- 관련 영역: CORE 상태 관리, DB, API다.
- 관련 요구사항: FR-12A, NFR-04다.
- 입력: API가 넘긴 인증 계정과 `node_id`다.
- 출력: 기기 장소의 소유권 일치 여부다.
- 바뀌는 상태: 없다.
- 약속: 조회·승인마다 CORE가 소유권을 검사한다. API는 인증 계정만 넘긴다.
- 지금 정해야 하는 이유: `NodeInfo`에는 장소 소유자가 없다. `Repository`에도 조회 접점이 없다.

### 선택지
- A. DB가 기기와 장소를 연결해서 소유권 일치 여부를 반환한다.
- B. DB가 장소 조회 모델을 제공한다. CORE가 인증 계정과 소유 계정을 비교한다.

### 제안
A를 제안한다. CORE는 소유권 일치 여부만 사용한다.

## 초안 2: 복구 안전 확인과 물리 상태 동기화

### 질문
점유 세션이 없거나 끝난 기기의 복구 검사 기준과 물리 상태 동기화 근거를 무엇으로 정하는가?

### 맥락
- 관련 영역: CORE 상태 관리, DB, IOT, 펌웨어다.
- 관련 요구사항: FR-12A, NFR-04다.
- 입력: 현재 기기 연결과 복구 건이다.
- 출력: 현재 연결에 유효한 안전 근거와 물리 상태 동기화 근거다.
- 바뀌는 상태: 복구 건의 근거다. 검사만으로 점유·사용분·기기 상태를 풀지 않는다.
- 약속: 안전 확인, 상태 동기화, 소유자의 복구 승인 순서를 지킨다.
- 지금 정해야 하는 이유: 반납 검사는 점유 세션의 검사 기준을 쓴다. 공용형과 종료한 세션의 기준 출처는 미결이다.

### 선택지
- A. 기기에 복구 검사 기준을 보존하고 기존 검사 요청 계약을 보완한다.
- B. 복구 전용 검사 기준과 결과 연결 계약을 제공한다.

### 제안
기기별 기준 출처와 결과 참조를 함께 정한다. 일반 `status`만으로 안전을 확정하지 않는다.
실제 기기의 시각 동기화와 허용 오차는 근접 추정 담당의 범위다.
