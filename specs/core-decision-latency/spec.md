# NFR-01 서버 판정 시간 검증

- 담당: eunji719 (판정)
- 요구사항: NFR-01
- 따르는 결정: 없음

## 1. 왜

- 서버 판정 시간의 기준(median 1초 이하, p95 2초 이하)을 검사하는 테스트가 없다. 판정 단계가 늘어도 느려졌는지 알 수 없다 (NFR-01, 지표 7).

## 2. 무엇

- 입력: 서로 다른 새 대여 요청 100건
- 출력: 요청마다 `DecisionPipeline.decide`가 걸린 시간의 median과 p95
- 바뀌는 상태: 없다. 요청마다 새 메모리 SQLite를 만든다.
- 약속:
  - 시간은 `decide` 호출 하나의 시작부터 반환까지다. 호스트와 네트워크, 근접 추정, 기기 실행 시간은 뺀다. 근접 추정과 실행 인계는 fake라서 이 테스트의 범위 밖이다.
  - 기준을 넘으면 테스트가 실패한다.

## 3. 제약

- 기준값은 요구사항의 값이다: median ≤ 1초, p95 ≤ 2초 (NFR-01, 지표 7).
- 판정 코드와 설정을 바꾸지 않는다.
- 판정 결과가 `OK`인 요청만 센다. 거부 판정이 섞이면 시간이 짧게 나온다.

## 4. 경계

### 고치는 곳
- `server/tests/integration/`

### 고치지 않는 곳
- 항상: `docs/`, `AGENTS.md` (Gotchas 절은 제외), `server/src/nearpilot/shared/`, `server/pyproject.toml`, `.github/`
- 이 작업: `server/src/`

### 다른 영역과 닿는 곳
| 계약 | 사용 또는 제공 | 상대 영역 |
|---|---|---|
| `DecisionPipeline.decide` | 사용 | 없음 (판정) |
| `SqliteRepository`, `RepositoryPolicyChecker` | 사용 (테스트 월드) | DB |

### 만들지 않는 것
- 발화부터 안내까지의 시간 (NFR-01의 둘째 요구). 호스트가 포함된 실측이라 자동 테스트로 검증할 수 없다.
- 실제 RSSI 모델과 기기 실행을 포함한 시간.
- 부하 상황의 시간.

## 5. 예외 상황
