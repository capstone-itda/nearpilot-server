# Intent: 상태 관리 역할 전체의 실행 수명주기·안전 종료·장애 복구

Author: JM-220 (상태 관리). Status: draft.

<!-- Status: draft → review → accepted. 대체되면 superseded 로 바꾸고 대체 문서를 링크한다. -->

## Problem

NearPilot은 실행 허가를 판정한 뒤에도 노드의 실행 여부, 장치의 물리 상태, 사용 세션, 승인 사용분을 일관되게 관리해야 한다. 예약이나 명령 전송만으로 실행 완료 또는 안전한 재사용을 보장할 수 없다.

현재 확인한 저장소에는 shared 모델·인터페이스와 일부 계약 테스트가 있지만, 상태 관리 담당 영역의 실행 수명주기·MQTT 게이트웨이·노드 시뮬레이터 구현은 아직 없다. 정상 흐름뿐 아니라 응답 유실, 중복·지연 사건, 안전 센서 이상, 서버·노드 재시작을 검증할 체계가 필요하다.

실행 결과 불명을 미실행으로 취급하면 이미 실행한 동작을 반복하거나 승인 사용분을 잘못 반환할 수 있다. 해제 요청만으로 장치를 재사용 가능하게 만들면 안전이 확인되지 않은 장치를 다음 사용자에게 허가할 수 있다. 장치 상태와 세션 상태를 혼동하면 FAULT 격리 과정에서 점유 근거와 복구에 필요한 기록을 잃을 수도 있다.

근거: FR-06·07·19·20·22, NFR-03·04. [PRD](../prd.md) §2~6과 [architecture](../architecture.md) §1·3·4·6·9를 따른다. 예약 이전 판정 흐름은 main에 반영된 [판정 파이프라인 intent](./core-decision-pipeline.md)를 참조한다. 재검사 분담의 기존 제안은 [PR #10 댓글](https://github.com/capstone-itda/nearpilot-server/pull/10#issuecomment-5978085565)을 참조한다.

## Proposed outcome

이 역할의 목적은 **허가된 요청을 확인 가능한 실행 결과로 연결하고, 사용 종료와 장애 상황에서도 안전하게 다음 사용으로 이어지는 상태를 유지하는 것**이다.

- **예약 이후 실행 흐름을 완성한다.** 판정 담당이 제공하는 실행 직전 재검사를 호출하고, 결과에 따라 실행·취소·보류·상태 전이를 처리한다. 실행 확인 전에는 완료로 취급하지 않는다.
- **장치 상태와 사용 세션을 구분한다.** 장치의 FAULT 격리와 세션의 진행·종료를 별도로 관리한다. 장치가 FAULT가 되었다는 이유로 불명확한 점유 세션을 삭제하거나 자동 종료하지 않는다.
- **사용 종료를 안전한 재사용으로 연결한다.** 대여형의 명시 해제·이탈 유예 만료·대여 타임아웃을 생성 당시 종료 정책에 따라 처리한다. 안전 종료 조건을 충족한 뒤에만 세션 종료와 장치 재사용을 확정한다.
- **통신 결과의 확실성을 보존한다.** MQTT 게이트웨이는 검증된 사건을 CORE에 전달하고, CORE가 허가한 명령만 전송한다. 확실한 미전송·실행 성공·실행 실패·결과 불명을 구분한다.
- **장애와 재시작 이후에도 진행 상태를 유지한다.** 필요한 기록을 복원하고, 실행 여부가 불명확하면 점유와 승인 사용분을 보류하여 FAULT 복구로 처리한다.
- **공용 조명의 의미를 유지한다.** 공용 조명에는 점유 세션과 CLOSING을 적용하지 않는다. 승인 사용분·실행 결과·장애 관리는 유지하고, 초기 이탈 자동 꺼짐은 비활성으로 둔다.
- **하드웨어 없이 검증할 수 있게 한다.** 노드 시뮬레이터와 대응 테스트로 정상·중복·지연·응답 유실·장애·재시작을 재현한다. 다른 담당의 구현이 없어도 shared 계약의 fake로 담당 범위를 검증할 수 있게 한다.

## Affected users and systems

- **방문자:** 실행 진행·완료·종료 상태를 신뢰할 수 있고, 다른 사용자의 요청이나 중복 사건으로 자신의 사용이 잘못 처리되지 않는다.
- **소유자·운영자:** FAULT 원인과 미결 실행·점유·승인 사용분을 확인하고, 안전 확인과 승인에 따라 복구할 수 있다.
- **상태 관리 담당 코드:** `server/src/nearpilot/core/lifecycle/`, `server/src/nearpilot/iot/`, `server/tools/node_sim/`와 대응 테스트.
- **판정 담당:** 최초 판정과 실행 직전 재검사 기능을 제공하고 예약 이후 흐름을 인계한다. 상태 관리가 반환하는 실행·종료 결과를 API 기능과 연결한다.
- **근접 추정 담당:** RSSI 관측과 비콘 수신 정보의 의미·전달 계약을 공유한다. 관측 모델·HMM·근접 추정은 해당 담당 영역으로 유지한다.
- **DB 담당:** 저장소·명령 기록·정책 스냅샷·승인 사용분·원자적 상태 반영·복원 조회·감사 저장 계약을 제공한다.
- **API·앱·대시보드 담당:** 사용자 인증과 외부 조회·해제·복구 접점을 구현한다. 상태 관리의 내부 기능 계약과 연결하되, UI·엔드포인트 구현은 이 intent의 담당 범위에 자동 포함하지 않는다.
- **펌웨어 담당:** MQTT 메시지와 명령 ID별 중복 방지·재시작 보존·안전 보고 계약을 공유한다. 실제 ESP32 펌웨어 구현은 별도 합의 범위다.
- **공동 영역:** shared 모델·인터페이스 변경과 `server/tests/integration/` 시나리오는 공동 검토한다.

## Constraints

1. **담당 경계와 재검사 분담**

   PRD → architecture → 합의된 intent의 권위 순서를 따른다. 최초 판정·실행 직전 재검사 기능은 판정 담당, 근접 추정은 근접 담당, 정책·승인 검사와 SQL·스키마·저장소·DB 트랜잭션 구현은 DB 담당의 책임이다.

   재검사 호출·실패 처리는 PR #10의 사용자 제안을 이어받아 상태 관리 담당이 맡는 방향으로 작성한다. 이는 이번 초안이 채택하는 분담 방향이며, 상대방의 명시적 확인까지 완료된 것으로 표시하지 않는다. 재검사에 통과하지 못하거나 확인할 수 없으면 실행하지 않는다. 자기 예약을 타인 점유로 보거나 확정 대상을 임의로 바꾸지 않는다. (FR-18, NFR-07)

2. **원자적 전이와 승인 정산**

   상태 관리가 전이·정산을 요청하고, DB 담당이 합의된 shared 계약으로 원자적으로 반영한다. 실행 성공·미전송 취소·결과 불명·안전 종료·FAULT 복구에서 장치·세션·명령·승인 사용분의 일관성을 유지한다. 현재 개별 조건부 갱신 함수의 연속 호출만으로 원자성이 보장된다고 가정하지 않는다.

   확실한 미전송 취소에만 예약·승인 사용분을 자동 반환한다. 노드의 실패 보고를 미전송과 같은 의미로 취급하지 않는다. 결과 불명은 보류·격리 후 실행 근거에 따라 정산한다. (FR-07·14·19·22, NFR-03)

3. **상태 구분과 재시작 보존**

   장치 상태는 `AVAILABLE/RESERVED/ACTIVE/CLOSING/FAULT`, 대여 세션 상태는 `RESERVED/ACTIVE/CLOSING/CLOSED`로 구분한다. FAULT는 불명확한 세션을 삭제하거나 자동 종료한 근거가 아니다.

   필요한 명령·진행 세션·승인 사용분 기록을 재시작 후에도 보존·복원한다. 진행 중 세션은 생성 당시 종료 정책과 만료 시각을 유지한다. 실행 여부를 확정하지 못하면 신규 허가를 차단하고 FAULT 복구로 처리한다. (FR-19·20·22, NFR-03·04)

   서버 프로세스 중단 중에는 서버의 타임아웃 검사·상태 전이가 진행되지 않는다. 재시작 시 합의된 예약 대기 제한을 지난 예약은 미전송이 확실한 경우에만 DB 계약으로 예약·승인 사용분을 원자적으로 반환하고, 반환된 예약의 명령 전송은 차단한다. 전송·실행 여부가 불명확하면 보류·FAULT 복구로 처리한다.

4. **MQTT 검증·인가·멱등성**

   MQTT 게이트웨이는 노드별 자격정보·노드 식별·메시지·명령 연결을 검증한 뒤 CORE에 전달한다. CORE 허가 없이 실행 명령을 보내거나 허가 여부를 자체 결정하지 않는다.

   새로운 `command_id`로 자동 재시도하지 않는다. 중복·늦은 사건으로 종료 상태를 되돌리거나 물리 실행·정산을 중복하지 않는다. 발표·재연결만으로 신뢰를 부여하거나 FAULT를 해제하지 않는다. 신뢰·온라인·장치 상태를 구분하고 독립 AP 환경을 전제로 한다. (FR-04~07·13·19, NFR-03·07·08·12)

5. **관측 전달과 이탈 처리의 책임**

   IOT는 검증된 RSSI 관측을 CORE에 전달한다. 상태 관리는 합의된 유효 관측을 이탈 처리에 사용하며 관측 모델·HMM·근접 판정을 재구현하지 않는다.

   유예 중 유효 비콘 재수신은 이탈 타이머를 초기화한다. CLOSING 진입 이후에는 재수신만으로 ACTIVE로 되돌리지 않고 종료를 계속한다. (FR-05·16·20, NFR-12)

6. **종료·안전·설정과 공용 조명**

   대여형은 명시 해제·타임아웃·이탈 유예 만료를 종료 정책에 따라 처리하며, 안전 확인 전에는 다음 사용자에게 허가하지 않는다. 해제·조회에는 본인 핸들 소유권과 필요한 권한 검사를 적용한다. 만료 후 안전 종료는 서버가 수행한다.

   FAULT 복구는 안전 확인·서버와 물리 상태 동기화·소유자 승인 후에만 허용한다.

   운영 수치는 설정으로 관리한다. PRD의 10초 미수신+5초 유예는 초기 기본값으로 취급하고, 미결 시간값·안전 조건을 임의 확정하지 않는다. 코드의 시연용 초기값을 확정 요구사항으로 승격하지 않는다. 현재 신뢰·온라인·안전 상태 검사는 계속 적용한다.

   공용 조명은 점유 세션·CLOSING을 사용하지 않으며 초기 이탈 자동 꺼짐은 비활성으로 유지한다. (FR-07·19·20·21, NFR-04)

7. **기록 보존·감사·공동 계약**

   실행·종료·복구와 적용 정책·설정의 근거를 보존하고 DB 감사 인터페이스로 기록한다. 감사 재현은 물리 명령을 재전송하지 않는다. 기록 삭제가 오래된 요청·명령의 재실행 허용으로 이어져서는 안 된다. (FR-19·22, NFR-03·13)

   계층 간에는 shared 인터페이스에 의존한다. 현재 동기 계약을 기준으로 후속 spec을 작성하며, shared 변경은 공동 계약 변경으로 구분하고 4인 리뷰를 받는다. 다른 담당의 구현을 상태 관리 영역으로 가져오지 않는다.

8. **문서와 검증 운영**

   이 문서는 역할 전체의 목적·범위·책임 경계·완료 조건을 정하는 상위 intent다. 세부 구현 단위별 intent와 spec은 1:1로 대응한다. intent는 문제·의도·기대 결과·제약·인수 조건을, spec은 구체 설계를 담는다. 각 문서를 리뷰한 뒤 구현한다.

   intent는 작성자 외 2인의 승인과 현재 문서 규칙을 따른다. 담당 FR마다 pytest 케이스를 두고 공동 통합 시나리오는 공동 소유로 관리한다. 시연 환경인 Windows와 독립 AP에서 검증할 수 있어야 한다.

   후속 문서는 게이트웨이·시뮬레이터·예약 이후 실행·안전 종료·FAULT 및 재시작 복구의 5개 단위로 나누는 것을 제안한다. 세부 intent·spec 본문은 별도로 작성한다.

## Open questions

기존 질문 번호를 유지한다. 정리된 원칙은 Constraints에 반영하고, 아래에는 남은 확인·계약·수치만 질문으로 둔다. 후속 합의가 이루어지면 항목을 삭제하지 않고 결론과 근거를 덧붙인다.

1. **예약 이후 인계와 재검사 계약**

   **정리된 내용:** 판정 담당이 재검사 기능을 제공하고 상태 관리 담당이 호출·실패 처리를 맡는 기존 제안을 이번 초안에서 이어받는다. PR #10은 main에 머지되었으나 판정 intent의 Open questions 3번에는 호출·실패 처리 분담이 질문으로 남아 있다. 머지 여부와 댓글 제안에 대한 명시적 확인·문서 반영을 구분한다. 실행·미전송 반환 원칙은 Constraints 1·2를 따른다.

   **남은 미결:** 이 분담 제안에 대한 판정 담당의 명시적 확인과 PR #10 문서 반영이 필요하다. 인계할 요청·확정 대상·예약·승인 사용분·판정 문맥, 재검사 함수의 입력·출력·사유·예외, 자기 예약 식별 방식, 실패 결과와 반환 요청의 연결 방식을 합의한다.

2. **원자적 상태 반영과 복구 정산 계약**

   **정리된 내용:** 상태 관리가 전이·정산을 요청하고 DB 담당이 원자적으로 저장한다. Constraints 2의 책임과 일관성 원칙을 따른다.

   **남은 미결:** 성공·취소·보류·종료·복구별로 함께 반영할 기록의 정확한 범위, shared 함수의 입력·반환값, 중복·경합·저장 실패 시 보장 범위를 정한다. 공용 조명의 승인 사용분 확보 접점도 포함한다.

3. **재시작 복원 정보와 시간 처리**

   **정리된 내용:** 필요한 기록을 복원하고 생성 당시 세션 정책·만료를 유지한다. 실행 여부 불명은 Constraints 3에 따라 처리한다.

   **남은 미결:** 복원 조회 모델·인터페이스와 필요한 필드 보완을 정한다. 현재 `UseSession`에 없는 종료 정책을 어떻게 제공할지, 이탈 타이머를 어떻게 복원할지, 서버 중단 시간을 미수신·유예 시간에 포함할지, 재시작 뒤 관측 공백을 무엇으로 판단할지 합의한다.

4. **MQTT 메시지와 늦은 결과 전달 계약**

   **정리된 내용:** 검증·허가 전달·중복 방지·상태 역행 금지 원칙은 Constraints 4를 따른다.

   **남은 미결:** 자격정보와 노드 ID 연결 방식, 페이로드 버전·시각·유효성, 사건 식별·중복·순서·신선도 기준을 정한다. `send()` 반환 이후 도착한 결과를 CORE에 전달하는 인터페이스와 노드 재시작 식별 방식을 펌웨어 담당과 맞춘다.

5. **비콘 매핑과 관측 사건의 인계**

   **정리된 내용:** IOT의 관측 전달, 근접 추정 담당의 모델 책임, 상태 관리의 이탈 처리 경계는 Constraints 5를 따른다.

   **이번 제안·미합의:** `BeaconKey → beacon_id` 매핑은 DB 저장소 내부에서 처리하도록 제안한다. 기존 합의로 간주하지 않고 DB 담당의 확인과 shared 전달 모델 영향을 검토한다.

   **남은 미결:** 유효 재수신을 판단할 계정·비콘 연결과 관측 시각 기준, RSSI 저장·근접 갱신·이탈 처리 사이의 전달 계약을 정한다.

6. **운영 시간값·안전 확인·복구 접점**

   **정리된 내용:** 설정 관리, 기존 세션 정책 유지, 안전 확인·동기화·소유자 승인 후 복구 원칙은 Constraints 6을 따른다.

   **남은 미결:** 실행 응답·예약 대기·온라인 TTL·대여 기본 타임아웃의 실제 값, 장치별 안전 센서 조합·상태 신선도, 실행 여부 확인 근거를 정한다. 소유자 권한 확인과 복구 승인 인계 접점은 API·DB 담당과 맞춘다.

7. **기록 보존과 오래된 요청·명령 거부 계약**

   **정리된 내용:** 필요한 처리 기록을 보존하고 기록 삭제로 재실행을 허용하지 않는 원칙은 Constraints 7을 따른다.

   **남은 미결:** 종료 이력·멱등 키·서버/노드 명령 기록의 보존기간·용량, 기록 삭제 이후 오래된 요청·명령을 식별하고 만료·거부할 구체 계약을 정한다.

공용 조명의 향후 이탈 자동 꺼짐은 다중 사용자 유지 기준 합의가 필요하지만, 초기 비활성 구현의 완료를 막는 선행 조건으로 삼지 않는다.
