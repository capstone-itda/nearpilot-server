# NearPilot 서버 PRD

> 기준 문서: [요구사항 분석서](../bedrock/NearPilot_요구사항분석서.md) (2026-09-17 제출). 이 PRD는 그중 **서버 저장소**가 책임지는 범위를 정리한다. 요구사항 ID(FR·NFR·UC)는 분석서를 따른다.

## 1. 한 줄 요약

Claude·ChatGPT·Gemini 같은 AI 호스트에 **MCP 엔드포인트를 직접 제공**하고, 계정·근처 비콘·접근 정책·점유 상태로 물리 기기의 **실행 허가(OK/BUSY)** 를 결정론적으로 판정하는 인증·판정 서버.

## 2. 문제

| 문제 | 설명 |
|---|---|
| 플랫폼·장소 종속 | 잠깐 머무는 장소의 기기는 전용 앱·가입 때문에 사실상 못 쓴다. |
| 다중 사용자 간섭 | 내 요청이 남의 기기에 적용된다. |
| 근접 판정 근거 부재 | LLM은 "어느 기기인지" 모르고, 고정 RSSI 임계값은 환경이 바뀌면 틀린다. |
| 호스트 신뢰 가정 | 허가를 호스트 확인 UI에 맡기지만 물리 동작은 되돌릴 수 없다. |

## 3. 목표와 비목표

### 목표

1. 3종 AI 호스트가 **같은 URL·같은 MCP 도구**로 주변 기기를 조회·요청한다 (FR-08~10, NFR-09).
2. 서버가 ⓪ 중복 → ① 비콘 → ② 후보 → ③ 근접 → ④ 정책 → ⑤ 장치 점유 → ⑥ 사용자 점유 순으로 판정하고, **기본값은 거부**다 (FR-18).
3. "어느 장치 앞인가"를 RSSI 관측 모델 + HMM으로 추정하고, 확신이 없으면 **되묻는다** (FR-16, FR-17).
4. 배타적 장치의 점유·해제를 서버가 **원자적으로** 관리한다 (FR-19, FR-20).
5. 모든 판정을 버전 정보와 함께 감사 로그로 남겨 **request_id로 재현**한다 (FR-22, NFR-13).

### 비목표 (이 저장소 범위 밖)

- Android 앱(FR-01~03 UI), ESP32 펌웨어(FR-04~07 노드 측), 운영 대시보드 프런트엔드 — 서버는 이들이 쓰는 API·MQTT 계약만 제공한다.
- 실제 잠금장치·고보안 출입문·게이트, iOS, 강한 단말 인증 (NFR-14).
- 서버 판정에 LLM 사용.

## 4. 사용자

| 액터 | 서버와의 접점 |
|---|---|
| 방문자 | AI 호스트를 통해 MCP 도구 호출. 앱을 통해 계정·비콘 1회 등록 |
| 소유자 / 설치자 | 대시보드 REST로 노드 신뢰·정책 설정·FAULT 복구, 앱으로 승인 처리 |
| AI 호스트 (외부) | MCP 클라이언트. 판정에는 관여하지 않으며 사용자 ID를 받지 않는다 |
| ESP32 노드 (내부) | MQTT로 기능 발표·RSSI 보고·실행 결과 보고, 서버의 OK를 받아야만 실행 |

## 5. 핵심 시나리오 — UC-04 "여기 사물함 열어줘"

1. 호스트가 `request_use(nearest:locker, open, request_id)` 호출
2. 서버가 토큰으로 계정 식별 → ⓪~⑥ 판정
3. 근접 사후확률 p(사물함 1) = 0.97 ≥ 0.95 → 대상 확정
4. 장치·사용자 미점유를 한 트랜잭션에서 확인하고 RESERVED
5. 노드에 `OK!(request_id)` → 실행 확인 → ACTIVE, use_id 발급
6. 호스트가 "1번 사물함을 열었습니다" 안내

분기: 재질문(ASK), 승인 필요(NEED_APPROVAL), 장치/사용자 점유(BUSY), 원격 요청(DENY), 중복 요청(기존 결과 반환), 실행 실패(FAULT 격리). 상세는 분석서 7장.

## 9. 제약과 가정

- 하드웨어: ESP32 + NimBLE, 사물함 3(서보·리드 스위치), LED 조명 3, 앵커 6개, 유효 반경 약 0.5 m (NFR-10).
- 저장소는 SQLite 단일 쓰기 경로 + `BEGIN IMMEDIATE` (FR-19, NFR-03).
- 고정 iBeacon은 복제 방지용 강한 인증이 아니다 (NFR-14).
- 관측·로그는 평가 후 계정 ID를 제거해 공개용 데이터셋으로 보존하고, 토큰 해시와 비콘 식별자는 프로젝트 종료 시 폐기한다.

## 10. 미결 사항

분석서에 값이나 정의가 없어 팀이 정해야 하는 항목. 결정 후 이 표를 갱신한다.

| # | 항목 | 관련 | 비고 |
|---|---|---|---|
| 1 | 비콘 최근 수신 기준 **T초** 값 | FR-15 | 수집 데이터로 결정 |
| 2 | **접근 정책 버전** 저장 위치 | FR-14, 부록 A | `approval.policy_version`·`request.policy_ver`가 참조하지만 `access_policy`에 version 컬럼이 없음 |
| 3 | "빈 사물함 아무거나"의 **target_spec 표기** | FR-23, A5 | 부록 A에는 `nearest:locker`와 `locker-1`만 있음 (예: `any:locker` 추가) |
| 4 | **해제 도구 이름** | FR-09 | 분석서에 이름이 나온 도구는 `find_available_devices`·`request_use`·`request_access`·`get_use_status`·`get_device_state` 5개. 해제 도구 이름은 없음 |
| 5 | `audit_log.request_id` **FK 제약** | 부록 A | 판정 단계 로그가 request 행보다 먼저 쓰이면 FK 위반 → 제약 없이 참조만 할지 결정 |
| 6 | 대여형 **기본 타임아웃** 값 | FR-20 | release_policy 기본값 |
