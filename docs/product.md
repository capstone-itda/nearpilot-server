## 문제

- 주변 기기를 쓰려면 방문자가 전용 앱을 설치하고 장소마다 가입해야 해서 번거롭다.
- 방문자가 기기를 잘못 선택한다.
- 여러 방문자가 서로 간섭한다.

## 사용자

| 사용자 | 제품과 만나는 지점 |
|---|---|
| 방문자 | Android 앱에서 계정과 비콘을 한 번 등록한다. 앱은 비콘을 백그라운드에서 송출한다. 방문자는 장소마다 등록하지 않고 AI 호스트로 기기를 조회하고, 사용하고, 해제한다. |
| 소유자 | Android 앱에서 접근 요청을 승인하거나 거부한다. 대시보드에서 기기 신뢰, 장소, 접근 정책을 설정하고 `FAULT` 기기를 복구한다. |
| AI 호스트 | Claude, ChatGPT, Gemini가 같은 MCP URL과 같은 도구를 쓴다. AI 호스트는 토큰으로 서버에 연결한다. AI 호스트는 사용자 ID를 입력하지 않고, 전달받지도 않는다. |
| 기기 | 기능 발표, RSSI, 안전 상태, 실행 결과를 MQTT로 서버에 보고한다. 기기는 서버가 보낸 명령을 실행한다. |

## 제품이 하는 일

NearPilot은 계정을 인증하고 요청을 판정하는 서버다. NearPilot은 AI 호스트가 전달한 자연어 요청을 주변 기기의 실제 사용으로 연결한다.

- 입력: AI 호스트가 전달한 방문자의 요청
- 출력: 주변 기기의 실행. 또는 기기를 실행하지 않은 판정과 사유
- 약속: NearPilot은 아래 원칙을 지킨다.

## 원칙

- 서버는 계정, 비콘 관측, 접근 정책, 점유 상태를 결정론적으로 검사한다.
- 기기는 서버가 허가한 요청만 실행한다.
- 서버는 LLM의 판단이나 AI 호스트의 확인 UI를 허가의 근거로 쓰지 않는다.

## 범위

### 포함

- 서버
  - MCP
  - 앱과 대시보드용 REST
  - 모니터링용 WebSocket
  - MQTT 연동
  - 근접 추정
  - 접근 정책과 승인
  - 점유와 해제
  - 기록과 평가
- 연동 계약: Android 앱 UI, ESP32 펌웨어, 대시보드 프런트엔드는 따로 구현한다. 서버는 세 구현과 연동하는 계약을 제공한다.

### 제외

- iOS
- 실제 잠금장치
- 고보안 출입문과 게이트
- 강한 단말 인증
- LLM을 이용한 서버 판정
