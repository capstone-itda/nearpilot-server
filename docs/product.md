## 문제

- 주변 기기를 쓰려면 방문자가 전용 앱을 설치하고 장소마다 가입해야 해서 번거롭다.
- 방문자가 기기를 잘못 선택한다.
- 여러 방문자가 서로 간섭한다.

## 사용자

| 사용자 | 제품과 만나는 지점 |
|---|---|
| 방문자 | Android 앱에서 계정과 비콘을 한 번 등록한다. 앱은 비콘을 백그라운드에서 송출한다. 방문자는 장소마다 등록하지 않고 AI 호스트로 기기를 조회하고, 사용하고, 해제한다. |
| 소유자 | Android 앱에서 접근 요청을 승인하거나 거부한다. 시드 스크립트로 기기 신뢰, 장소, 접근 정책을 설정한다. 스크립트로 `FAULT` 기기를 복구한다. |
| 운영자 | 대시보드로 판정, 기기 상태, 감사 로그를 실시간으로 본다. 대시보드는 서버에 쓰지 않는다. |
| AI 호스트 | Claude, ChatGPT, Gemini가 같은 MCP URL과 같은 도구를 쓴다. AI 호스트는 토큰으로 서버에 연결한다. AI 호스트는 사용자 ID를 입력하지 않고, 전달받지도 않는다. |
| 기기 | 기능 발표, RSSI, 명령 처리 상태와 실행 결과를 MQTT로 서버에 보고한다. 기기는 서버가 보낸 명령의 제어 신호를 출력한다. |

## 제품이 하는 일

NearPilot은 계정을 인증하고 요청을 판정하는 서버다. NearPilot은 AI 호스트가 전달한 자연어 요청을 주변 기기의 실제 사용으로 연결한다.

- 입력: AI 호스트가 전달한 방문자의 요청
- 출력: 주변 기기의 제어 신호 출력 결과. 또는 기기를 실행하지 않은 판정과 사유
- 약속: NearPilot은 아래 원칙을 지킨다.

## 원칙

- 서버는 계정, 비콘 관측, 접근 정책, 점유 상태를 결정론적으로 검사한다.
- 기기는 서버가 허가한 요청만 실행한다.
- 서버는 LLM의 판단이나 AI 호스트의 확인 UI를 허가의 근거로 쓰지 않는다.
- 대여형 기기는 방문자가 떠나거나 대여시간을 초과해도 점유를 유지한다. 서버는 초과시간을 계산한다.
- 방문자가 명시적으로 반납하면 서버는 본인 점유와 미완료 명령, 장애 상태를 검사한 뒤 점유를 해제한다.
- 공용형 기기는 유지 대상자가 모두 떠나면 서버가 꺼짐을 요청한다. 서버는 켜진 시간만으로 꺼짐을 요청하지 않는다.
- 실행 성공은 펌웨어가 명령의 제어 신호 출력을 마치고 결과를 저장했다는 뜻이다. 실제 켜짐, 열림, 재생은 보장하지 않는다.
- 반납 완료는 서버가 논리적 점유를 해제했다는 뜻이다. 문 닫힘과 잠금은 보장하지 않는다.
- 운영 수치는 시연용 초기 기준이다. 서버는 운영 수치를 설정으로 관리한다.

## 범위

### 포함

- 서버
  - MCP
  - 앱과 대시보드용 REST
  - 모니터링용 WebSocket
  - MQTT 연동
  - 근접 추정
  - 접근 정책과 승인
  - 점유와 해제
  - 기록과 평가
- 연동 계약: Android 앱 UI, ESP32 펌웨어, 대시보드 프런트엔드는 따로 구현한다. 서버는 세 구현과 연동하는 계약을 제공한다.

### 제외

- iOS
- 실제 잠금장치
- 고보안 출입문과 게이트
- 강한 단말 인증
- LLM을 이용한 서버 판정
- 대여 초과시간에 따른 추가금 부과
- 센서를 이용한 실제 상태 확인과 물리 완료 검증
- 센서 기반 반납 검사와 물리 안전 확인

### 결정과 구현의 구분

2026-10-26에 센서 기반 물리 상태 검증을 범위에서 제외했다. BLE 비콘과 RSSI를 이용한 근접 추정은 유지한다.
이 결정은 서버 허가, 접근 정책, 점유, 중복 실행 방지와 명령 만료 검사를 유지한다.
문서 변경은 구현 완료를 뜻하지 않는다. 후속 구현 범위는 `architecture.md` §4 "공동 인터페이스의 후속 반영"에 쓴다.
문서별 영향과 보존 이유는 [센서 검증 제외의 문서 영향 점검](sensor-removal-review.md)에 쓴다.
